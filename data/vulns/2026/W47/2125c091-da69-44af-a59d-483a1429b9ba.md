# In the Linux kernel, the following vulnerability has been resolved\: 9p/trans\_virtio\: reject mount tags longer than NAME\_MAX at probe p9\.\.\.

- **ID**: CVE\-2026\-99785
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
9p/trans\_virtio\: reject mount tags longer than NAME\_MAX at probe
  
p9\_virtio\_probe\(\) reads a 16\-bit mount tag length \(tag\_len\) from the  
device config and kzalloc\(\)s tag\_len \+ 1 bytes for chan\-&gt;tag with no  
upper bound\. A malicious or compromised host can present a tag of up to  
65535 bytes; that tag is later copied into the single\-page sysfs buffer  
by p9\_mount\_tag\_show\(\) \(memcpy\(buf, chan\-&gt;tag, tag\_len \+ 1\)\), a  
host\-controlled out\-of\-bounds write of up to \~64 KiB past the PAGE\_SIZE  
attribute buffer\.
  
Reject an overlong tag at probe time\. A 9p mount tag is a name\-like  
identifier, so bound it by NAME\_MAX \(255\)\: that limit is independent of  
the sysfs/seq\_file page size and is far above any legitimate mount tag,  
which keeps p9\_mount\_tag\_show\(\) safe at the root without hard\-coding a  
seq\_file implementation detail\.
