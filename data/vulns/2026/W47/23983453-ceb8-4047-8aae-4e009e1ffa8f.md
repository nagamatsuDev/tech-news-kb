# In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the ueba\_finding\_exclusion\_edit capability could create\.\.\.

- **ID**: CVE\-2026\-131210
- **危険度**: High（重要） (CVSS 8.1)
- **公開**: 2026-11-19

## 原文

In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the ueba\_finding\_exclusion\_edit capability could create a finding exclusion rule that references an attacker\-controlled lookup definition if the role also grants write access to globally shared lookup definitions, as the "ess\_analyst" Splunk Enterprise Security role does\. The User and Entity Behavior Analytics \(UEBA\) Content App could later include the lookup name in a search and run arbitrary Search Processing Language \(SPL\) commands with elevated permissions\. With this access, the user who created the finding exclusion rule could expose stored credentials and other data outside the permissions assigned to the "ess\_analyst" role\.  
The vulnerability is possible because UEBA finding exclusion processing does not safely quote lookup names before including them in SPL searches\.  
For more information see Finding exclusions in Splunk Enterprise Security \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/administer/8\.3/user\-and\-entity\-behavior\-analytics/finding\-exclusions\-in\-splunk\-enterprise\-security\) and Roles and knowledge objects in UEBA for Splunk Enterprise Security \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/administer/8\.8/user\-and\-entity\-behavior\-analytics/ueba\-content\-app\-for\-on\-premises/roles\-and\-knowledge\-objects\-in\-ueba\-for\-splunk\-enterprise\-security\) in the Splunk documentation\.
