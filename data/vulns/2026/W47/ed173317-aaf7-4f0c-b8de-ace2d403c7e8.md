# In the Linux kernel, the following vulnerability has been resolved\: vhost\: fix used ring index wrap in vhost\_add\_used\_n\_in\_order vhost\_\.\.\.

- **ID**: CVE\-2026\-99686
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
vhost\: fix used ring index wrap in vhost\_add\_used\_n\_in\_order
  
vhost\_add\_used\_n\_in\_order\(\) advances start by nheads\[i\] but wraps it  
with a single subtraction\.  If start \+ nheads\[i\] &gt;\= 2 \* vq\-&gt;num, start  
can remain outside the ring\.
  
With used\-ring logging enabled, start &gt; vq\-&gt;num makes \(vq\-&gt;num \- start\)  
underflow\.  log\_write\(\) then sets bits beyond the dirty\-log bitmap,  
potentially corrupting adjacent userspace memory\.  This is reachable on  
the vhost\-net TX path with VIRTIO\_F\_IN\_ORDER\: done\_idx can reach  
VHOST\_NET\_BATCH \(64\), triggering the issue with a 32\-entry ring\.
  
Wrap start with a mask to keep it within the ring\.  VHOST\_SET\_VRING\_NUM  
enforces a nonzero power\-of\-two ring size, allowing start to be wrapped  
using &amp; \(vq\-&gt;num \- 1\)\.
