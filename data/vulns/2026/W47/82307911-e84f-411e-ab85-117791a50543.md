# In the Linux kernel, the following vulnerability has been resolved\: net\: sched\: prevent scheduling deactivated qdiscs TAPRIO can schedu\.\.\.

- **ID**: CVE\-2026\-99457
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
net\: sched\: prevent scheduling deactivated qdiscs
  
TAPRIO can schedule a deactivated qdisc after some\_qdisc\_is\_busy\(\) has  
reported it idle\.
  
Commit 47e8dbb6e763 \("net/sched\: do not reset queues in graft operations"\)  
made graft deactivation skip queue reset, leaving TAPRIO's timer armed\.
  
A late callback schedules NET\_TX softirq work, whose dequeue path can  
race the unlocked child\-queue reset in taprio\_reset\(\)\. The same skb can  
be queued for deferred freeing by RTNL and dequeued for transmission\.  
In the reproducer, the TAP reader frees it before \_\_rtnl\_unlock\(\) reads  
its next pointer\. KASAN reports a slab\-use\-after\-free in  
\_\_rtnl\_unlock\+0xa3/0xd0, with a read of size 8 from the freed skb\.
  
Reject deactivated qdiscs in \_\_netif\_schedule\(\)\. Callers' RCU protection  
lets the existing grace period join earlier scheduling calls before the  
busy check\. Restart nonempty transmit queues on reactivation so suppressed  
scheduling does not strand packets\.
