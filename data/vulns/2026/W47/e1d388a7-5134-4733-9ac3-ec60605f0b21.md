# In the Linux kernel, the following vulnerability has been resolved\: drm/loongson\: Fix double free on BO initialization failure If ttm\_b\.\.\.

- **ID**: CVE\-2026\-99753
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
drm/loongson\: Fix double free on BO initialization failure
  
If ttm\_bo\_init\_validate\(\) fails, it drops the buffer object's reference  
and cleans it up through the supplied destroy callback\. lsdc\_bo\_destroy\(\)  
releases the GEM object and frees the enclosing lsdc\_bo, so freeing it  
again in lsdc\_bo\_create\(\) causes a double free on a synchronous failure  
path\.
  
Let TTM own the cleanup after initialization has started and return the  
error directly\. Keep the explicit free on drm\_gem\_object\_init\(\) failure,  
which occurs before ownership is passed to TTM\.
  
Tested on LS7A2000 by making drm\_vma\_offset\_add\(\) return \-ENOSPC for one  
selected dumb\-buffer creation\. The error reached userspace, the destroy  
callback ran once, and no handle was published or tracked BO retained\.  
Normal buffer creation, zeroing, mapping, readback and release passed\.
  
AI assistance was used for the ownership analysis, fix, fault\-injection  
tools, build and test execution\.
