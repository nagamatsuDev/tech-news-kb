# The Model Context Protocol Python SDK is the official Python SDK for Model Context Protocol servers and clients\.

- **ID**: CVE\-2026\-115563
- **危険度**: High（重要） (CVSS 7.5)
- **言語**: Python
- **公開**: 2026-11-16

## 原文

The Model Context Protocol Python SDK is the official Python SDK for Model Context Protocol servers and clients\. From 1\.9\.1 until 1\.30\.0 and 2\.2\.0, OAuth client support in mcp\.client\.auth can send credentials to an authorization server chosen by an untrusted MCP server\. ClientCredentialsOAuthProvider and PrivateKeyJWTOAuthProvider cannot identify the authorization server that owns their credentials\. Affected HTTP clients using those providers, OAuthClientProvider, or the deprecated 1\.x RFC7523OAuthClientProvider can disclose a client\_secret, authorization code, PKCE code\_verifier, or signed client assertion\. MCP servers, stdio clients, and clients that attach their own tokens or headers are not affected\. Interactive OAuthClientProvider use requires a person to start sign\-in, while the unattended providers do not\. For ClientCredentialsOAuthProvider and PrivateKeyJWTOAuthProvider, callers must configure issuer\= after upgrading because omission still follows the MCP server's advertised authorization server, and the deprecated RFC7523OAuthClientProvider must be replaced because it has no issuer option\. A stored client registration without an issuer remains unbound after upgrading, so stored OAuth client information must be cleared once to register again or a manually pre\-registered record must be updated with its issuer\. This issue is fixed in versions 1\.30\.0 and 2\.2\.0\.
