# mail\-parser\: One hostile attachment aborts \`write\_attachments\(\)\` and silently drops the rest of the batch

- **ID**: CVE\-2026\-129301 / GHSA\-8cgq\-x343\-p74c
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: Python
- **パッケージ**: PyPI/mail\-parser &gt;\= 4\.6\.0, &lt; 4\.6\.3 → 4\.6\.3
- **公開**: 2026-11-16

## 原文

\#\#\# Impact \`write\_attachments\(\)\` called \`\_safe\_attachment\_filename\(\)\` and \`write\_sample\(\)\` inside its loop with no guard, so a single crafted attachment raised out of the whole save\. Every attachment \*\*after\*\* the malicious one was silently never written, with no error surfaced to a caller that catches only \`MailParserError\`\. That is an evasion primitive as much as an availability bug\: a sender puts one poisoned part first and the real payload second, and the payload never reaches the extraction directory that a downstream scanner or sandbox reads — while it still reaches the recipient's mail
