# In the Linux kernel, the following vulnerability has been resolved\: ocfs2/dlm\: hold the lookup reference across convert AST enqueue dlm\.\.\.

- **ID**: CVE\-2026\-99432
- **危険度**: High（重要） (CVSS 8.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ocfs2/dlm\: hold the lookup reference across convert AST enqueue
  
dlm\_convert\_lock\_handler\(\) drops the reference it took when it found the  
lock on res\-&gt;granted at its leave label, one statement before it calls  
dlm\_queue\_ast\(\)\.  dlm\_free\_dead\_locks\(\) takes res\-&gt;spinlock and drops the  
list and base references, so a peer death landing in that gap leaves the  
handler's own put as the one that frees the lock, and \_\_dlm\_queue\_ast\(\)  
then reads lock\-&gt;lockres from freed memory\.
  
The handler is registered next to dlm\_create\_lock\_handler\(\), so a convert  
message buffered on a dying peer's socket arrives on the same o2net  
receive work that o2net\_disconnect\_node\(\) does not wait for\.  The two can  
interleave as follows, with the reference counts as they are before this  
fix\:
  
  Socket data\-ready       Node\-down thread      Receive worker  
  \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-       \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-      \-\-\-\-\-\-\-\-\-\-\-\-\-\-  
  o2net\_data\_ready\(\)  
    select sc under  
    callback read lock  
                          o2net\_disconnect\_node\(\)  
                            queue shutdown  
                            begin flush; new color  
    queue sc\_rx\_work  
    in the new color  
    release callback lock  
                            shutdown socket  
                            flush returns  
                                                read buffered convert\_lock  
                                                dlm\_convert\_lock\_handler\(\)  
                                                  find lock on res\-&gt;granted  
                                                  dlm\_lock\_get\(\)  refs \= 3  
                                                  lock res\-&gt;spinlock  
                                                  \_\_dlmconvert\_master\(\)  
                                                    call\_ast \= 1  
                                                  unlock res\-&gt;spinlock  
                          DLM node\-down cleanup  
                            lock res\-&gt;spinlock  
                            dlm\_free\_dead\_locks\(\)  
                              unlink lock  
                              put list ref  refs \= 2  
                              put base ref  refs \= 1  
                            unlock res\-&gt;spinlock  
                                                dlm\_lock\_put\(\)  refs \= 0  
                                                  free lock  
                                                dlm\_queue\_ast\(\)  
                                                  \_\_dlm\_queue\_ast\(\)  
                                                  read lock\-&gt;lockres  
                                                  \(use\-after\-free\)
  
\_\_dlmconvert\_master\(\) only moves the lock between lists, so the count  
entering the gap is base, list and lookup\.  Drop the lookup reference  
after the AST is queued instead of before it and the race ends with the  
one \_\_dlm\_queue\_ast\(\) took, which dlm\_flush\_asts\(\) releases later with  
ast\_pending cleared and ast\_list unlinked\.  No extra get is needed, and  
the normal case ends with the same count as before\.
  
dlmconvert\_master\(\) has the same shape but is only reached from dlmlock\(\)  
for a lock this node owns, which dlm\_free\_dead\_locks\(\) never matches\.
