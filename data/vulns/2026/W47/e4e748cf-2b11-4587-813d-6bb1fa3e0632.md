# In the Linux kernel, the following vulnerability has been resolved\: ALSA\: hwdep\: Serialize DSP load requests The check of the loaded DS\.\.\.

- **ID**: CVE\-2026\-99317
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-18

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ALSA\: hwdep\: Serialize DSP load requests
  
The check of the loaded DSP indices and the call of the driver's  
dsp\_load callback in snd\_hwdep\_dsp\_load\(\) are not serialized\.  A hwdep  
file descriptor can be shared among threads, or inherited across fork,  
so two SNDRV\_HWDEP\_IOCTL\_DSP\_LOAD requests for the same index can both  
observe the index as unloaded and enter the driver's callback  
concurrently, even though the device itself is opened exclusively\.
  
This breaks the assumption behind hw\-&gt;dsp\_loaded that a firmware index  
is loaded only once\.  For example, snd\-usb\-usx2y hits  
WARN\_ON\(usx2y\-&gt;as04\.buffer\) in usx2y\_async\_seq04\_init\(\) and may  
allocate the US\-428 sequence URBs twice\.
  
Serialize the check, the callback invocation and the bookkeeping with a  
per\-hwdep mutex, so that the second request returns \-EBUSY\.
