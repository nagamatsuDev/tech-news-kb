# PHP\-FPM request smuggling through an unread HTTP request body\.

- **ID**: CVE\-2026\-129289
- **危険度**: Critical（緊急） (CVSS 9.2)
- **言語**: PHP
- **公開**: 2026-11-19

## 原文

PHP\-FPM request smuggling through an unread HTTP request body\.
  
PHP does not discard the unread part of an HTTP request body at request shutdown when the application has opened php\://input without reading it to the end\. When the front end reuses backend connections, which is not the default in nginx or Apache \(for example nginx with fastcgi\_keep\_conn on, or Apache mod\_proxy\_fcgi with enablereuse\=on\), PHP\-FPM can parse the leftover bytes as a new FastCGI request\. An unauthenticated remote attacker can use a single crafted multipart/form\-data request to forge a backend request with chosen parameters such as SCRIPT\_FILENAME, REMOTE\_ADDR and PHP\_ADMIN\_VALUE, which can lead to execution of attacker\-controlled PHP code\. With LSAPI, subsequent requests on the connection can be disrupted\.
  
This issue affects PHP versions before 8\.2\.36, 8\.3\.\* before 8\.3\.37, 8\.4\.\* before 8\.4\.28 and 8\.5\.\* before 8\.5\.13\.
