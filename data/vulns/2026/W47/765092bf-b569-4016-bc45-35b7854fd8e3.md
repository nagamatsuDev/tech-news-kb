# NLTK\: ZIP package extraction follows in\-root hardlinks and overwrites files outside the NLTK data root

- **ID**: CVE\-2026\-128135 / GHSA\-wr3g\-j6qj\-xpgh
- **危険度**: High（重要） (CVSS 7.1)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.9\.4, &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Summary NLTK ships a security wrapper, \`nltk\.pathsec\.ZipFile\`, that is meant to confine archive extraction to trusted data roots and to block link\-based escapes\. When \`nltk\.download\(\)\` installs a package, the extraction write opens each member's target path without checking whether that path is a hardlink to a file located outside the data root\. A local actor who can write inside a shared or predictable NLTK data root \(for example \`\~/nltk\_data\`, a group\-writable \`/usr/share/nltk\_data\`, or a shared container volume\) can pre\-plant an in\-root hardlink at a member path that a soon\-to\-be\-install
