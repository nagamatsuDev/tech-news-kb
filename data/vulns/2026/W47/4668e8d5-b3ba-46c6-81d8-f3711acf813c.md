# In the Linux kernel, the following vulnerability has been resolved\: ovl\: hold a reference on the parent in readdir Listing a directory \.\.\.

- **ID**: CVE\-2026\-99425
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ovl\: hold a reference on the parent in readdir
  
Listing a directory on an overlay uses a freed dentry and crashes the  
kernel when a lookup moves the directory at the same time\.
  
Code that can sleep may only use d\_parent without a reference while  
something stops a move of the dentry\. ovl\_iterate\_real\(\),  
ovl\_need\_adjust\_d\_ino\(\) and ovl\_cache\_update\(\) use the d\_parent of the  
listed directory and hold only the lock of that directory\. When a  
lookup finds the directory under another parent after a change to a  
layer, d\_splice\_alias\(\) moves it without that lock and drops its  
reference on the old parent\.
  
With a delay in ovl\_iterate\_real\(\), getdents64 on an overlay directory  
raced a rename in the lower layer and a lookup that moved its dentry,  
and after an rmdir of the old parent KASAN reported a use\-after\-free in  
security\_inode\_getattr\(\)\.
  
Fix this by using dget\_parent\(\) in the three functions\.
  
\[amir\: fix comments in ovl\_need\_adjust\_d\_ino\(\)\]
