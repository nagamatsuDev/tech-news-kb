# In the Linux kernel, the following vulnerability has been resolved\: ksmbd\: fix app\-instance non\-durable supersede session UAF ksmbd\_clo\.\.\.

- **ID**: CVE\-2026\-99289
- **危険度**: High（重要） (CVSS 8.8)
- **OS**: Linux
- **公開**: 2026-11-16

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ksmbd\: fix app\-instance non\-durable supersede session UAF
  
ksmbd\_close\_fd\_app\_instance\_id\(\) supersedes a prior open that has the  
same AppInstanceId\. It reaches that open's session through opinfo\-&gt;sess\.  
This pointer is not refcounted\.
  
Session teardown detaches durable handles before it frees the session\.  
It does not detach a non\-durable open\. That open still points at the  
session through opinfo\-&gt;sess after the session is freed\. Another session  
can supersede the open at the same time\. The supersede then takes a  
write lock through the stale pointer, in the freed session's file table\.
  
  BUG\: KASAN\: slab\-use\-after\-free in \_raw\_write\_lock\+0x71/0xd0  
  Call Trace\:  
   \_raw\_write\_lock\+0x71/0xd0  
   ksmbd\_close\_fd\_app\_instance\_id\+0xd9/0x670 \[ksmbd\]  
   smb2\_open\+0x3e10/0xd910 \[ksmbd\]  
  Freed by task 212\:  
   ksmbd\_session\_destroy\+0x38d/0x480 \[ksmbd\]
  
Fix this by looking the session up by opinfo\-&gt;session\_id\. The lookup  
returns a reference, as smb2\_break\_collect\_channels\(\) does\. Recheck that  
opinfo\-&gt;sess still points at it before using it\.
  
Do the lookup without m\_lock held\. destroy\_previous\_session\(\) takes  
m\_lock under the session table lock, and taking them in the other order  
here would deadlock\.
