# In the Linux kernel, the following vulnerability has been resolved\: x86/mm\: Fix global ASID handed out to two processes On AMD CPUs wit\.\.\.

- **ID**: CVE\-2026\-99592
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
x86/mm\: Fix global ASID handed out to two processes
  
On AMD CPUs with INVLPGB, two live processes can get the same MAX\_ASID\_AVAILABLE  
global ASID value\. The two then hit each other's TLB entries, so each can read  
or corrupt the other's memory\.
  
The global ASID space is managed lazily\. When a global ASID is freed, its bit is  
set in the global\_asid\_freed bitmap\. Once the free ASID search reaches the end  
of the global\_asid\_used bitmap, a global flush is done to really reclaim the  
lazily freed global ASIDs\.
  
However, the current code can assign the same global ASID to two different  
processes, if one process is assigned MAX\_ASID\_AVAILABLE \- 1, another process  
MAX\_ASID\_AVAILABLE, and both stick around \(keeping their global ASID numbers in  
use\) until the search wraps around again\.  At that point a third process could  
also get assigned MAX\_ASID\_AVAILABLE\.
  
    the highest ASID stays in use, so it is not handed out again  
      last\_global\_asid stays below it, so no reset  
        the clear bits run out  
          find\_next\_zero\_bit\(\) returns MAX\_ASID\_AVAILABLE  
            global\_asid\_available &gt; 0, so the failure is not caught  
              MAX\_ASID\_AVAILABLE is handed out as an ASID
  
A search only looks at the bits below MAX\_ASID\_AVAILABLE, so it cannot see that  
this value is in use\. The next failed search hands it out again, even if the  
first process still holds it\.
  
The fix used here is to reset the global ASID space after a failed search, and  
to search again\. If that search fails too, no global ASID is handed out\.
  
The test for \!global\_asid\_available is removed, because use\_global\_asid\(\) only  
calls allocate\_global\_asid\(\) if global\_asid\_available &gt; 0\. The remaining test is  
for a condition that should be impossible\.
