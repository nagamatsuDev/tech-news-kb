# eml\_parser\: Algorithmic\-complexity DoS \(O\(n\^4\) regex backtracking\) in Received\-header parsing

- **ID**: CVE\-2026\-129307 / GHSA\-m4g8\-47f9\-h588
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/eml\-parser &lt;\= 3\.0\.3 → 3\.0\.4
- **公開**: 2026-11-19

## 原文

\#\#\# Summary \`eml\_parser\.routing\.parserouting\(\)\` dynamically builds a regex from up to four greedy \`\.\*\` groups \(\`from \(?P&lt;from&gt;\.\*\)by \(?P&lt;by&gt;\.\*\)with \(?P&lt;with&gt;\.\*\)for \(?P&lt;for&gt;\.\*\)\`\) terminated by an escaped literal of the date extracted from a \*\*normalized\*\* copy of the \`Received\` header\. Because the date literal comes from the normalized text but is searched in the original line, a crafted header can make the trailing literal unmatchable; the search then fails at every start position only after exhaustively backtracking the four nested greedy groups — \*\*O\(n\^4\)\*\* in header length\. A single \~5\.9 KB
