# In the Linux kernel, the following vulnerability has been resolved\: mm/huge\_memory\: fix truncate racing with PMD zapping zap\_huge\_pmd\_f\.\.\.

- **ID**: CVE\-2026\-99669
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/huge\_memory\: fix truncate racing with PMD zapping
  
zap\_huge\_pmd\_folio\(\) removes the rmap before calling folio\_mark\_dirty\(\)\.  
If this was the last mapping, truncation can skip unmapping the folio  
and proceed without waiting for the PMD lock, racing with dirtying\.
  
ifs\_set\_range\_dirty\(\) can oops if MADV\_DONTNEED races with  
ftruncate\(\) on XFS, when we get the folio set dirty after it was found  
to not be mapped anymore\.
  
Move folio\_mark\_dirty\(\) and folio\_mark\_accessed\(\) before rmap removal,  
matching the PTE zap path\. This keeps the folio mapped while updating  
its state, so truncation must wait for the page table lock\.
  
Fix generated by an LLM and sent by Chris Mason in private\.
