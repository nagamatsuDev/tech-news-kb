# In the Linux kernel, the following vulnerability has been resolved\: ksmbd\: fix OOB read and cross\-share confusion in ksmbd\_validate\_name\.\.\.

- **ID**: CVE\-2026\-99541
- **危険度**: High（重要） (CVSS 8.3)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ksmbd\: fix OOB read and cross\-share confusion in ksmbd\_validate\_name\_reconnect\(\)
  
ksmbd\_validate\_name\_reconnect\(\) indexes  
ab\_pathname\[share\-&gt;path\_sz \+ 1\] without checking that the path is  
longer than share\-&gt;path\_sz \+ 1 \(d\_path\(\) fills the buffer from the  
end\)\. A durable fp is not bound to its original share, so a client  
can preserve a file from a short\-path share and reconnect it on a  
long\-path share, making strcmp\(\) read past the PATH\_MAX buffer \-  
with a long enough share path this oopses the kernel, and on a  
mapped page it also gives a byte\-equality oracle on adjacent heap  
\(the reconnect succeeds exactly when the out\-of\-bounds string  
equals the requested name\)\. A same\-share variant with the durable  
fp at the share root reads 1 byte past the buffer  
\(strlen\(ab\_pathname\) \=\= share\-&gt;path\_sz\)\.
  
Check before comparing\: the path must be longer than share\-&gt;path\_sz,  
it must start with share\-&gt;path, and the next character must be '/'\.  
The share root itself is accepted only for an empty name\.
