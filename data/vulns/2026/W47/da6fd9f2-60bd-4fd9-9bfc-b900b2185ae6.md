# In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the ueba\_finding\_exclusion\_edit capability could store \.\.\.

- **ID**: CVE\-2026\-131215
- **危険度**: High（重要） (CVSS 8.3)
- **公開**: 2026-11-19

## 原文

In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the ueba\_finding\_exclusion\_edit capability could store attacker\-controlled values in a User and Entity Behavior Analytics \(UEBA\) finding exclusion rule\. Splunk Enterprise Security could later run attacker\-controlled Search Processing Language \(SPL\) commands from the rule with elevated permissions\. With this access, the user could cause Splunk Enterprise Security to read stored credentials and modify lookups and knowledge objects\.  
The vulnerability is possible because the UEBA finding exclusion workflow does not escape user\-controlled rule values before using them in generated SPL\.  
For more information see Create a finding exclusion rule using UEBA configuration page \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/administer/8\.7/user\-and\-entity\-behavior\-analytics/finding\-exclusions\-in\-splunk\-enterprise\-security/create\-a\-finding\-exclusion\-rule\-using\-ueba\-configuration\-page\) and Users and roles for Splunk Enterprise Security \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/install/8\.7/installation/users\-and\-roles\-for\-splunk\-enterprise\-security\) in the Splunk documentation\.
