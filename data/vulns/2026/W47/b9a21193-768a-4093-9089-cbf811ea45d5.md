# In the Linux kernel, the following vulnerability has been resolved\: ovl\: use the pinned upper dir in ovl\_fix\_origin\(\) Renames made dire\.\.\.

- **ID**: CVE\-2026\-99422
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ovl\: use the pinned upper dir in ovl\_fix\_origin\(\)
  
Renames made directly on the upper filesystem during a lookup crash the  
kernel\.
  
A dentry that is passed to vfs\_setxattr\(\) must be pinned\.  
ovl\_fix\_origin\(\) passes upper\-&gt;d\_parent to ovl\_set\_impure\(\) without a  
reference, and the lookup holds no lock of the upper directory\. A  
rename on the upper filesystem changes d\_parent, and only the child  
pins the new parent, so a second rename and an rmdir free it\.
  
With delays in ovl\_fix\_origin\(\) and ovl\_set\_impure\(\), renaming the upper  
directory twice and removing the intermediate parent during the lookup  
of a merge directory without an origin xattr gave a KASAN  
use\-after\-free in vfs\_setxattr\(\)\.
  
Fix this by passing the upper dentry that the overlay parent holds\.
  
\[amir\: add helper ovl\_set\_impure\_dir\(\)\]
