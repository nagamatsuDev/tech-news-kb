# In the Linux kernel, the following vulnerability has been resolved\: sctp\: account for chunk padding in sctp\_init\_cause\(\) sctp\_init\_caus\.\.\.

- **ID**: CVE\-2026\-99758
- **危険度**: High（重要） (CVSS 7.5)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
sctp\: account for chunk padding in sctp\_init\_cause\(\)
  
sctp\_init\_cause\(\) accepts a chunk when skb\_tailroom\(\) can hold the  
cause header and the payload\. sctp\_addto\_chunk\(\) then writes 0\-3  
bytes of padding before that header so the chunk stays 4\-byte  
aligned\. The check does not include the padding, and the following  
skb\_put\(\) calls skb\_over\_panic\(\) from softirq\.
  
Count the padding sctp\_addto\_chunk\(\) is about to write\. The cause  
length on the wire stays the header plus the payload\.
  
Found by LLM inspection, triggered and tested the fix\.
