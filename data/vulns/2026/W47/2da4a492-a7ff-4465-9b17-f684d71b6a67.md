# NLTK\: ARFF\_Formatter Injects Weka ARFF Schema Directives via Attacker\-Controlled Class Labels

- **ID**: CVE\-2026\-129221 / GHSA\-9ffx\-rrgx\-mhgx
- **危険度**: Medium（警告） (CVSS 5.4)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Description \#\#\# Summary \`nltk\.classify\.weka\.ARFF\_Formatter\` writes class labels directly into the Weka ARFF \`@ATTRIBUTE '\-label\-' \{\.\.\.\}\` declaration without any ARFF quoting or escaping\. An attacker who can contribute class labels to a training dataset can include ARFF metacharacters such as \`\}\`, newlines, \`@ATTRIBUTE\`, and \`@DATA\` to break out of the nominal label list and inject attacker‑controlled ARFF schema and data directives\. This vulnerability is reachable in any application that calls \`WekaClassifier\.train\(\)\` or \`ARFF\_Formatter\.from\_train\(\)\` with attacker‑influenced training data\.
