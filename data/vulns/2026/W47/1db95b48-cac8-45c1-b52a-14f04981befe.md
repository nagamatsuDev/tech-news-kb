# Directus\: Share update allows reassigning user\_created and role

- **ID**: CVE\-2026\-129239 / GHSA\-7h45\-q5jx\-7r87
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: JavaScript/TypeScript
- **パッケージ**: npm/directus &lt; 12\.3\.1 → 12\.3\.1
- **公開**: 2026-11-16

## 原文

\#\#\# Summary A non\-admin user who can update their own shares can reassign a share's creator \(\`user\_created\`\), \`role\`, \`item\`, and \`collection\` fields after the share is created\. The update is authorized against the row as it existed before the change, and the resulting row is never revalidated, so these fields can be set to values the user would not be permitted to assign when creating a share\. By reassigning both \`user\_created\` and \`role\` to an administrator the share's effective permissions get elevated\. This is a server\-side authorization gap in the share update path\.
