# In the Linux kernel, the following vulnerability has been resolved\: ALSA\: usx2y\: Initialize idle URBs before submitting streams usb\_str\.\.\.

- **ID**: CVE\-2026\-99316
- **危険度**: High（重要） (CVSS 7.0)
- **OS**: Linux
- **公開**: 2026-11-18

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ALSA\: usx2y\: Initialize idle URBs before submitting streams
  
usb\_stream\_start\(\) submits the first two capture and playback URBs and  
only afterwards assigns sk\-&gt;idle\_inurb, sk\-&gt;idle\_outurb,  
sk\-&gt;completed\_inurb and sk\-&gt;completed\_outurb to the remaining two URBs  
of each direction\.
  
A transfer can complete as soon as usb\_submit\_urb\(\) has been called, so  
the completion handler i\_capture\_start\(\) or i\_playback\_start\(\) may run  
before those pointers are set\.  While the stream is still being  
synchronized \(state below usb\_stream\_sync1\), stream\_start\(\) then calls  
playback\_prep\_freqn\(sk, sk\-&gt;idle\_outurb\) with sk\-&gt;idle\_outurb still  
NULL, and the packet descriptors are written through that NULL pointer\:
  
  Oops\: general protection fault, probably for non\-canonical address  
  0xdffffc0000000018\: 0000 \[\#1\] SMP KASAN  
  KASAN\: null\-ptr\-deref in range \[0x00000000000000c0\-0x00000000000000c7\]  
  RIP\: 0010\:playback\_prep\_freqn\+0x11c/0x4a0 sound/usb/usx2y/usb\_stream\.c\:33  
  Call Trace\:  
   &lt;IRQ&gt;  
   stream\_start\+0x5dc/0x8d0 sound/usb/usx2y/usb\_stream\.c\:596  
   i\_capture\_start\+0x3da/0x710 sound/usb/usx2y/usb\_stream\.c\:654  
   \_\_usb\_hcd\_giveback\_urb\+0x238/0x550 drivers/usb/core/hcd\.c\:1657  
   usb\_giveback\_urb\_bh\+0x20b/0x530 drivers/usb/core/hcd\.c\:1691  
   tasklet\_hi\_action\+0xa/0x20 kernel/softirq\.c\:994  
   handle\_softirqs\+0x16f/0x440 kernel/softirq\.c\:645  
   &lt;/IRQ&gt;
  
The four URBs referenced by these pointers are allocated long before and  
do not depend on any transfer state, so assign them before the submit  
loop\.  Keeping the assignment inside the retry path also restores a  
well\-defined URB rotation when the start frame mismatch handling kills  
and resubmits the streams\.
