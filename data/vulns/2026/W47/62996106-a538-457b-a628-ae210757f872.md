# django\-filer\: Missing per\-object authorization on \`discard\` and \`edit\_redirect\` version transitions

- **ID**: CVE\-2026\-69131 / GHSA\-vf85\-8ff2\-3r9w
- **危険度**: Medium（警告） (CVSS 4.3)
- **言語**: Python
- **パッケージ**: PyPI/django\-filer &lt;\= 3\.4\.4 → 3\.5\.0
- **公開**: 2026-11-18

## 原文

\#\# Summary When django\-filer's optional per\-folder permission system is enabled \(\`FILER\_ENABLE\_PERMISSIONS\=True\`\), the "Delete files and/or folders" admin action does \*\*not\*\* enforce per\-folder edit permissions the way every other mutating action does\. A staff user who is scoped \*\*read\-only\*\* on a folder via \`FolderPermission\` \(\`can\_edit \= DENY\`\), but who holds the global Django model\-level \`delete\_\*\` permission, can delete files and entire subfolders inside that folder — even though their move, rename, copy, and resize actions on the same folder are correctly denied\. This is an integrity / ed
