# In the Linux kernel, the following vulnerability has been resolved\: ipv6\: raw\: fix use\-after\-free in rawv6\_send\_hdrinc\(\) rawv6\_send\_hdr\.\.\.

- **ID**: CVE\-2026\-99320
- **危険度**: High（重要） (CVSS 7.0)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ipv6\: raw\: fix use\-after\-free in rawv6\_send\_hdrinc\(\)
  
rawv6\_send\_hdrinc\(\) caches the route before handing the skb to  
l3mdev\_ip6\_out\(\)\. The VRF output path may replace skb\-&gt;dst and release  
the original route, leaving the cached pointer stale\.
  
The function later dereferences that pointer for statistics accounting  
and as the output device passed to NF\_HOOK\(\)\. Its RCU read\-side critical  
section starts after l3mdev\_ip6\_out\(\), so it cannot prevent the old route  
from being reclaimed in between\.
  
Reload the route from the current skb destination after  
l3mdev\_ip6\_out\(\) returns\.
  
KASAN reports a slab\-use\-after\-free in rawv6\_sendmsg\(\), with the route  
allocated by ip6\_dst\_alloc\(\), freed by dst\_destroy\(\) from rcu\_core\(\), and  
the related RCU callback queued from vrf\_l3\_out\(\)\.
