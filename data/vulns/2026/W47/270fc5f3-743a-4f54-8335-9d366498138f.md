# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: validate NT transaction response layout and offsets va\.\.\.

- **ID**: CVE\-2026\-99380
- **危険度**: High（重要） (CVSS 8.1)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: validate NT transaction response layout and offsets
  
validate\_ntransact\(\) assumes that the response uses the fixed 18\-word NT  
transaction layout\. A different WordCount makes get\_bcc\(\) locate the byte  
count at a different offset from pSMBr\-&gt;ByteCount, allowing the subsequent  
bounds checks to use inconsistent response boundaries\.
  
The function also turns the 32\-bit ParameterOffset and DataOffset fields  
into pointers before checking their bounds\. On a 32\-bit client, a large  
offset can wrap the pointer below end\_of\_smb and pass the one\-sided pointer  
comparison\. The caller then dereferences the parameter pointer or copies  
from the data pointer\.
  
Require the expected WordCount before reading the byte count\. Check each  
offset and count against the received SMB length as integers before forming  
either pointer\. Use subtraction after validating the offset so that the  
range checks cannot overflow\.
