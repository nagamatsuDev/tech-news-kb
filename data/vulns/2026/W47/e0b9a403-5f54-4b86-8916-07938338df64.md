# In the Linux kernel, the following vulnerability has been resolved\: mm/filemap\: finish fault cleanup before dropping the fault lock On \.\.\.

- **ID**: CVE\-2026\-99730
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/filemap\: finish fault cleanup before dropping the fault lock
  
On a retried fault, a fatal signal interrupting the folio lock wait  
makes lock\_folio\_maybe\_drop\_mmap\(\) drop the fault lock without pinning  
the file\. However, filemap\_fault\(\) may still need to release  
mapping\-&gt;invalidate\_lock\. A concurrent munmap\(\) can release the last  
file reference and free the mapping before that unlock\.
  
Defer dropping the fault lock to filemap\_fault\(\)'s retry cleanup, after  
releasing invalidate\_lock\. If the fault lock was already dropped for  
I/O, release the existing file reference instead\. Keep the fault lock  
held for FAULT\_FLAG\_RETRY\_NOWAIT as before\.
