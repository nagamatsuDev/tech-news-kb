# NLTK\: Uncontrolled recursion in Tree\.fromlist causes denial of service via deeply nested list input

- **ID**: CVE\-2026\-129227 / GHSA\-63wh\-5r5m\-wxr7
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Root Cause \`Tree\.fromlist\` \(\`nltk/tree/tree\.py\:767\`\) converts a nested list into a \`Tree\` by recursing once per nesting level \(\`nltk/tree/tree\.py\:780\`\) with no depth bound — its only validation is \`type\(l\) \=\= list and len\(l\) &gt; 0\`\. The sibling constructor \`Tree\.fromstring\` was hardened with a \`MAX\_TREE\_DEPTH\` cap \(\`nltk/tree/tree\.py\:31,695\`\) that rejects adversarially deep input with a bounded \`ValueError\`, but that guard was not applied to \`fromlist\`, which builds \`Tree\` objects identically\. \#\# Impact An application that builds a \`Tree\` from an attacker\-controlled nested list — for example
