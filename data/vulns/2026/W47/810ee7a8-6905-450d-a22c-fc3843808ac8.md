# Issue summary\: When an application passes a stack to PEM\_X509\_INFO\_read\_bio\_ex\(\) to add entries to, and reading fails, OpenSSL frees ever\.\.\.

- **ID**: CVE\-2026\-107493
- **危険度**: High（重要） (CVSS 7.7)
- **公開**: 2026-11-17

## 原文

Issue summary\: When an application passes a stack to  
PEM\_X509\_INFO\_read\_bio\_ex\(\) to add entries to, and reading fails,  
OpenSSL frees every entry in the stack, both the old ones and any new  
ones, but leaves them in the stack\.
  
Impact summary\: An application that passes an existing stack to  
PEM\_X509\_INFO\_read\_bio\_ex\(\) and keeps using it after a failed read may  
use memory that was already freed\. This can cause a crash or, in  
principle, memory corruption\. Malformed PEM data can make the read fail,  
but only applications that pass an existing stack are affected, and  
OpenSSL itself does not do this\.
  
CWE\: CWE\-416\: Use After Free
  
Description\: PEM\_X509\_INFO\_read\_bio\_ex\(\) reads certificates, CRLs and  
private keys from PEM data and adds them to a stack of X509\_INFO  
structures\. If the application passes a stack that is not NULL, the  
function adds the new entries to it and must leave the entries that are  
already there unchanged\.
  
If reading fails, the function frees every entry in the stack\. This  
includes the entries that were there before the call, and the entries  
added by the call\. It does not remove these entries from the stack, so  
the stack keeps pointers to freed memory\. The failure can happen at any  
point, even before any entry was added\. A PEM item with invalid content  
is enough\.  This also happens if the stack was empty\: entries added  
before the failure are freed but stay in the stack\.
  
An application that then reads or frees the stack will use memory that  
was already freed\. This can crash the application or, in principle,  
corrupt memory\.
  
Only applications that pass a stack that is not NULL are affected\.  
OpenSSL itself never does this\. Its own callers, including the code that  
TLS uses to load CA certificates, always pass NULL\. When the stack is  
NULL, the function frees only the entries that it created itself, which  
is safe\. We expect that very few applications pass an existing stack\. An  
attacker can make the read fail with malformed PEM data, but cannot make  
an application pass an existing stack\.
  
The same problem affects PEM\_X509\_INFO\_read\_bio\(\), PEM\_X509\_INFO\_read\(\)  
and PEM\_X509\_INFO\_read\_ex\(\), which use the same code\. OpenSSL 1\.1\.1 and  
1\.0\.2 have only the first two of these functions\.
  
FIPS impact\: no  
The affected code is outside the FIPS module boundary\.
