# NLTK\: Uncontrolled recursion in semantic\-logic type parser causes denial of service via nested type strings

- **ID**: CVE\-2026\-129226 / GHSA\-w3pv\-xfw4\-ghr7
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Root Cause The semantic\-logic type parser \`read\_type\` \(\`nltk/sem/logic\.py\:866\`\) recurses on both halves of every \`&lt;a,b&gt;\` complex type \(\`nltk/sem/logic\.py\:882\-884\`\) with no depth or length bound — only an \`isinstance\` assertion and a parenthesis\-balance assertion\. The \`LogicParser\.MAX\_PARSE\_DEPTH\` guard \(\`nltk/sem/logic\.py\:107,294\`\) protects the expression parser but never runs on the \`read\_type\` path, which is reached directly by the public \`Type\.fromstring\` classmethod and by signature\-string type checking\. \#\# Impact An application that parses an untrusted type string, or type\-checks an ex
