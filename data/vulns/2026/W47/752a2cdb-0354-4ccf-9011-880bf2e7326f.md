# In the Linux kernel, the following vulnerability has been resolved\: fbdev\: udlfb\: don't rebuild the mode list while the framebuffer is i\.\.\.

- **ID**: CVE\-2026\-99305
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-16

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
fbdev\: udlfb\: don't rebuild the mode list while the framebuffer is in use
  
dlfb\_setup\_modes\(\) frees info\-&gt;modelist with fb\_destroy\_modelist\(\) and  
rebuilds it, but fbcon holds raw pointers into that list in  
fb\_display\[i\]\.mode and nothing un\-publishes them the way  
do\_unregister\_framebuffer\(\) and store\_modes\(\) do with  
fbcon\_delete\_modelist\(\)\. The function does refuse to install a new mode  
while the framebuffer has users \(dlfb\-&gt;fb\_count \!\= 0\), but only after the  
list is already destroyed\. Reached from the 0666 "edid" sysfs attribute,  
an unprivileged write to /sys/class/graphics/fb0/edid therefore fails with  
\-EINVAL and still leaves every fb\_display\[i\]\.mode dangling; the next  
console switch reads the freed fb\_videomode in fb\_videomode\_to\_var\(\)\.
  
Test fb\_count before touching the list\. fbcon takes a reference through  
fbcon\_open\(\), so that condition covers exactly the states in which  
fb\_display\[\] points into the list, and the errno returned to userspace is  
unchanged\.
