# Improper Input Validation vulnerability in phoenixframework phoenix \(Phoenix\.Presence\) allows an attacker who can join a channel to cause\.\.\.

- **ID**: CVE\-2026\-128361
- **危険度**: High（重要） (CVSS 8.2)
- **公開**: 2026-11-21

## 原文

Improper Input Validation vulnerability in phoenixframework phoenix \(Phoenix\.Presence\) allows an attacker who can join a channel to cause a denial of service via a non\-string presence key\.
  
track/3,4 accepts any term as the presence key, such as a JSON object taken from a join payload\. The key is converted with to\_string/1 only later, in Phoenix\.Presence\.group/1, which raises Protocol\.UndefinedError on a map\. group/1 runs whenever presences are listed and when each presence diff is broadcast, together with the application's fetch/2, which can likewise raise on an unexpected key\. Once such a key is tracked, every process that lists presences on the topic crashes, typically each channel that joins it, and presence diffs for the topic are lost\.
  
From 1\.7\.0 the diff runs in a Task\.Supervisor\.async task linked to the tracker shard, and Phoenix\.Presence\.handle\_info/2 has no clause for its failure\. The shard then terminates, taking down every channel and LiveView process tracked on it and erasing presence state for all its topics\. Repeated joins exhaust the restart intensity and take down the application supervisor\.
  
This issue affects phoenix\: from 1\.2\.0 before 1\.5\.16, from 1\.6\.0\-rc\.0 before 1\.6\.18, from 1\.7\.0\-rc\.0 before 1\.7\.25, and from 1\.8\.0\-rc\.0 before 1\.8\.17\.
