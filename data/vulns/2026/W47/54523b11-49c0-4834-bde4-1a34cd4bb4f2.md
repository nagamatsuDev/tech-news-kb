# \#\#\# Summary ui With \`strip\_ansi\=True\`, Pydantic AI Harness's \`ToolOutputLimits\` capability removes ANSI escape sequences from tool outpu\.\.\.

- **ID**: CVE\-2026\-133161
- **危険度**: High（重要） (CVSS 7.5)
- **公開**: 2026-11-19

## 原文

\#\#\# Summary ui
  
With \`strip\_ansi\=True\`, Pydantic AI Harness's \`ToolOutputLimits\` capability removes ANSI escape sequences from tool output with a pattern that takes time quadratic in the length of a line\. A tool result of a few hundred kilobytes, crafted with many unterminated escape sequences, can occupy the event loop for tens of seconds to minutes, delaying every other request and agent run in the process\.
  
\#\#\# Details
  
This affects applications that set \`strip\_ansi\=True\` on \`ToolOutputLimits\` \(named \`OverflowingToolOutput\` before 0\.13\.0\) and run tools whose output an attacker can influence, such as shell commands, file reads, fetched pages or MCP servers\. Stripping runs on the event loop before the capability reduces the output, so its own size limits do not bound it\.
  
The assumed attacker can place text in content a tool returns\.
  
\#\#\# Mitigation
  
Upgrade \`pydantic\-ai\-harness\` to 0\.70\.0 or later\. Until then, leave \`strip\_ansi\` at its default, \`False\`\.
  
On Pydantic AI v1, the harness cannot be upgraded past 0\.4\.0\. Upgrade to Pydantic AI v2 and \`pydantic\-ai\-harness\` 0\.70\.0, or leave \`strip\_ansi\` off\.
