# The SMSC911x/LAN9220 Ethernet driver stages every outgoing frame in a fixed\-size static buffer before pushing it to the controller FIFO\.

- **ID**: CVE\-2026\-95826
- **危険度**: High（重要） (CVSS 7.5)
- **公開**: 2026-11-20

## 原文

The SMSC911x/LAN9220 Ethernet driver stages every outgoing frame in a fixed\-size static buffer before pushing it to the controller FIFO\. eth\_tx\(\) in drivers/ethernet/eth\_smsc911x\.c took the frame length from net\_pkt\_get\_len\(pkt\) and passed it directly to net\_pkt\_read\(pkt, tx\_buf, total\_len\), with no comparison against the size of tx\_buf \(NET\_ETH\_MAX\_FRAME\_SIZE\)\. net\_pkt\_read\(\) takes no destination size and only fails when the packet is shorter than the requested length, so any packet longer than the staging buffer was copied past its end\.
  
Nothing between the IP layer and the driver bounds the frame to what the link can carry\: ethernet\_send\(\) in subsys/net/l2/ethernet/ethernet\.c performs no length check, and the IPv6 output path only compares the packet against the interface MTU when CONFIG\_NET\_IPV6\_FRAGMENT is enabled \(it is disabled by default\)\. The size the stack will build is therefore governed by the interface MTU, and that MTU is remotely settable\: handle\_ra\_input\(\) in subsys/net/ip/ipv6\_nbr\.c honours the MTU option of any Router Advertisement with a value up to 0xffff, gated only by the standard hop\-limit\-255 and link\-local\-source checks\. An unauthenticated attacker on the same link can raise the MTU and then have the device emit a single frame of several kilobytes, for example as a TCP segment from any service that returns more than \~1\.5 KB or as an oversized UDP datagram\.
  
The result is an out\-of\-bounds write into \.bss immediately after tx\_buf, with the overrun length and much of its content derived from the transmitted frame\. Consequences range from corruption of adjacent kernel data and a crash to potential control\-flow influence where the clobbered globals hold pointers; the practical overrun size is bounded by the network buffer pool rather than by the advertised MTU\. The fix rejects frames larger than NET\_ETH\_MAX\_FRAME\_SIZE with \-EMSGSIZE before any TX\_DATA\_PORT write, so the controller FIFO is also not left holding a command word without its payload\.
