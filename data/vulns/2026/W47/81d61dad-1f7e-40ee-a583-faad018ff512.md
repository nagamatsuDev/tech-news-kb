# split\: TOCTOU output\-open allows truncating a swapped file

- **ID**: CVE\-2026\-35374 / GHSA\-fjjq\-8hw5\-cf9f
- **危険度**: Medium（警告） (CVSS 6.3)
- **言語**: Rust
- **パッケージ**: crates\.io/uu\_split &lt;\= 0\.9\.0 → 0\.10\.0
- **公開**: 2026-11-20

## 原文

\`split\` checks input/output identity by path before opening the output, then opens with truncation, leaving a race window on mutable path components\. GNU opens first and compares the opened output inode against the input before truncating\. The race can cause \`split\` to truncate/write a file different from the one validated — including the input file or another file the process can access\. \*\*Fixed in 0\.10\.0\*\* \(PR \#12565, commit 58040feb5c66fce588a7ffac299b3a23bd55cd81\)\: the output open path is hardened against TOCTOU target swaps\. \-\-\- \_Zellic private finding \(zellic\-ext/coreutils\-private PR \#11
