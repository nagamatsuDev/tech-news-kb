# NLTK\: Symlink escape in chat80\.sql\_query bypasses the pathsec data\-root sandbox to read out\-of\-root SQLite databases

- **ID**: CVE\-2026\-126302 / GHSA\-xmfg\-f9cm\-w86q
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.9\.4, &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-16

## 原文

\#\# Summary \`nltk\.sem\.chat80\.sql\_query\(\)\` opens a SQLite database by handing the result of \`nltk\.data\.find\(dbname\)\` straight to \`sqlite3\.connect\(\)\` without the path\-containment check that the NLTK data sandbox \(\`nltk\.pathsec\`\) is meant to enforce\. \`nltk\.data\.find\(\)\` applies only lexical checks to the resource name and returns a \`FileSystemPathPointer\` whose path is normalized with \`os\.path\.abspath\` but never resolved for symlinks\. As a result, an in\-root symbolic link that points at a SQLite file outside every registered NLTK data root is followed by SQLite, and the caller receives query result
