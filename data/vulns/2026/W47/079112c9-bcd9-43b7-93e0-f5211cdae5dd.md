# XWiki Platform\: HQL injection in search allows unauthenticated database extraction including password hashes

- **ID**: CVE\-2026\-61689 / GHSA\-jmmc\-wjpc\-pg34
- **危険度**: High（重要）
- **言語**: Java/Kotlin
- **パッケージ**: Maven/org\.xwiki\.platform\:xwiki\-platform\-rest\-server &gt;\= 4\.3\-milestone\-1, &lt; 16\.10\.18 → 16\.10\.18, Maven/org\.xwiki\.platform\:xwiki\-platform\-rest\-server &gt;\= 18\.0\.0\-rc\-1, &lt; 18\.2\.0 → 18\.2\.0, Maven/org\.xwiki\.platform\:xwiki\-platform\-rest\-server &gt;\= 17\.0\.0\-rc\-1, &lt; 17\.10\.5 → 17\.10\.5
- **公開**: 2026-11-17

## 原文

\#\#\# Impact The query REST API allows executing HQL queries to filter the listed pages\. While this properly checks access rights for the current user, the query can be used to combine when clauses and blind queries, to recover values, through FROM clause injection to join BaseObject and StringProperty tables, bypassing the HQL validator's SELECT column whitelist\. This allows recovering any data that is stored in the database, including data from inaccessible pages, password hashes and passwords stored in configuration properties\.
