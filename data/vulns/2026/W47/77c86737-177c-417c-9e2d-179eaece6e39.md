# Use\-after\-free via repopulation of last\_fatal\_error\_backtrace global after shutdown\.

- **ID**: CVE\-2026\-129182
- **危険度**: Critical（緊急） (CVSS 9.2)
- **言語**: PHP
- **公開**: 2026-11-19

## 原文

Use\-after\-free via repopulation of last\_fatal\_error\_backtrace global after shutdown\.
  
A fatal error raised while modified INI settings are restored during request shutdown can repopulate the stored fatal error backtrace after the executor has been cleaned up\. The request memory is then freed, and a diagnostic emitted before executor initialization in a later request handled by the same PHP\-FPM or mod\_php worker can access the stale backtrace\. The shutdown error requires per\-path configuration of max\_memory\_limit, or of zlib\.output\_compression together with output\_handler \(which \.user\.ini can also set\)\. The early diagnostic requires Apache per\-directory configuration or, for PHP\-FPM, a PHP\_VALUE or PHP\_ADMIN\_VALUE parameter sent by the front end\. This can cause memory corruption and worker crashes, and may allow remote code execution\.
  
This issue affects PHP versions 8\.5\.\* before 8\.5\.13\.
