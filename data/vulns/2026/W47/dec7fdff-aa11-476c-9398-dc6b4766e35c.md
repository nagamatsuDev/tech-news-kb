# In the Linux kernel, the following vulnerability has been resolved\: xfs\: reject out\-of\-range attribute value lengths in xfs\_attr\_copy\_va\.\.\.

- **ID**: CVE\-2026\-99400
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
xfs\: reject out\-of\-range attribute value lengths in xfs\_attr\_copy\_value
  
xfs\_attr\_copy\_value\(\) takes the value length as a signed int and, for a  
remote xattr, is handed args\-&gt;rmtvaluelen\.  That field is filled from the  
on\-disk \_\_be32 xfs\_attr\_leaf\_name\_remote\.valuelen in  
xfs\_attr3\_leaf\_getvalue\(\), so a crafted length such as 0x80000000 is  
stored into the signed rmtvaluelen as a negative number\.
  
The "buffer too small" guard in xfs\_attr\_copy\_value\(\) is a signed  
comparison\:
  
	if \(args\-&gt;valuelen &lt; valuelen\)  
		return \-ERANGE;
  
A negative valuelen therefore compares as smaller than the caller's  
buffer size, skips the \-ERANGE path, and is then used as a copy length,  
leading to an out\-of\-bounds copy of a full remote block into a small  
getxattr\(2\) buffer on a mounted crafted image\.
  
Reject a value length that is negative or larger than the maximum xattr  
size before it is used, so a bogus on\-disk length can no longer slip  
through the value copier\.
