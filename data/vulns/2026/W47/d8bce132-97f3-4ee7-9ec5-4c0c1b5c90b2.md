# In the Linux kernel, the following vulnerability has been resolved\: fs/proc/task\_mmu\: pin mm\_users in do\_pagemap\_scan\(\) The PAGEMAP\_SCA\.\.\.

- **ID**: CVE\-2026\-99477
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
fs/proc/task\_mmu\: pin mm\_users in do\_pagemap\_scan\(\)
  
The PAGEMAP\_SCAN ioctl takes mmap\_read\_lock\(\) on an mm obtained from  
/proc/&lt;pid&gt;/pagemap without holding a reference to mm\_users\.
  
proc\_mem\_open\(\) deliberately grabs only mm\_count, so a consumer that  
touches the address space has to call mmget\_not\_zero\(\) first\.  Every other  
consumer in this file does \-\- m\_start\(\), do\_procmap\_query\(\),  
show\_smaps\_rollup\(\) and pagemap\_read\(\) \-\- but do\_pagemap\_scan\(\) does not\.
  
Without that reference the target can reach exit\_mmap\(\) concurrently, and  
exit\_mmap\(\) calls unmap\_vmas\(\) while holding mmap\_lock only for reading,  
which does not exclude the scanner\.  For ordinary VMAs this is harmless,  
as free\_pgtables\(\) and remove\_vma\(\) run afterwards under mmap\_write\_lock\.   
A shared hugetlb VMA is different\: \_\_hugetlb\_zap\_end\(\) frees the VMA's  
hugetlb\_vma\_lock inside the read\-locked phase\.
  
walk\_hugetlb\_range\(\) can therefore load vma\-&gt;vm\_private\_data, have the  
lock freed underneath it, and then down\_read\(\) a freed rw\_semaphore\.  The  
load happens before the freeing side clears the pointer, so this is a  
use\-after\-free and not a NULL dereference\.  Any unprivileged user can  
reach it with no huge pages configured, as hugetlb\_reserve\_pages\(\)  
allocates the lock before the VM\_NORESERVE early return\.
  
Pin mm\_users across the scan, the way the other consumers do\.  mmput\(\)  
from the exiting task can then no longer reach exit\_mmap\(\) while a walk is  
in progress\.
  
\[akpm@linux\-foundation\.org\: remove unneeded &amp; undesirable test for \!mm\]
