# Mareforma\: transparency\_logged trusts the unsigned rekor block

- **ID**: CVE\-2026\-71534 / GHSA\-xfq4\-8hf9\-5h43
- **危険度**: Medium（警告）
- **言語**: Python
- **パッケージ**: PyPI/mareforma &gt;\= 0\.3\.0, &lt; 0\.3\.8 → 0\.3\.8
- **公開**: 2026-11-19

## 原文

\#\# What's wrong During restore, \`transparency\_logged\` is recomputed as \`1 if \(toml\_logged is not False and bundle\_has\_rekor\) else 0\`, where \`bundle\_has\_rekor\` comes only from a \`rekor\.uuid\` field inside \`signature\_bundle\`\. That derivation is wrong in both directions\. First, the rekor block is metadata attached after signing \(\`attach\_rekor\_entry\` in \`mareforma/signing/rekor\.py\` leaves the payload and signatures untouched\), so it is not covered by the Ed25519 signature\. A hand\-edited \`claims\.toml\` can add \`"rekor"\: \{"uuid"\: "x"\}\` to any claim's bundle and forge the "publicly witnessed by Rekor"
