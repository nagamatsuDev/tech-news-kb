# In the Linux kernel, the following vulnerability has been resolved\: mm/mmu\_notifier\: set \-&gt;mm only after mmgrab\(\) Radeon uses a non\-NUL\.\.\.

- **ID**: CVE\-2026\-99657
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/mmu\_notifier\: set \-&gt;mm only after mmgrab\(\)
  
Radeon uses a non\-NULL notifier\-&gt;mm to decide whether to call  
mmu\_interval\_notifier\_remove\(\) when freeing a buffer object\.  
\_\_mmu\_interval\_notifier\_insert\(\) sets \-&gt;mm before validating the range,  
so a wrapping userptr range can leave \-&gt;mm set after insertion fails\.  
Cleanup then tries to remove an unregistered notifier for which no mm  
reference was acquired\.
  
Set \-&gt;mm only after mmgrab\(\), once insertion can no longer fail\. While  
we could fix radeon's code instead, setting \-&gt;mm on success only makes  
the code more robust\.
  
Fix generated by an LLM and sent by Chris Mason in private\.
