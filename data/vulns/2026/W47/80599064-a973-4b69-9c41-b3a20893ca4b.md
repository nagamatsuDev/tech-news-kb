# In the Linux kernel, the following vulnerability has been resolved\: nvmet\-fc\: fix use\-after\-free in nvmet\_fc\_ls\_create\_connection\(\) nvm\.\.\.

- **ID**: CVE\-2026\-99516
- **危険度**: High（重要） (CVSS 7.1)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
nvmet\-fc\: fix use\-after\-free in nvmet\_fc\_ls\_create\_connection\(\)
  
nvmet\_fc\_ls\_create\_connection\(\) looks up the association with  
nvmet\_fc\_find\_target\_assoc\(\), which returns it with a reference held,  
and drops that reference as soon as the target queue has been allocated\.  
iod\-&gt;assoc is then dereferenced again by nvmet\_fc\_makeconnid\(\) while  
building the connection id\.
  
The queue only borrows the pointer and takes no reference of its own\.  
Once the lookup reference is dropped the association is kept alive  
solely by the reference taken when it was created, so a disconnect LS or  
a remote port unregister running concurrently can free it before  
nvmet\_fc\_makeconnid\(\) reads it\:
