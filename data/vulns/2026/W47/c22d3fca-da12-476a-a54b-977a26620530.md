# NLTK\: Uncontrolled recursion in DependencyGraph traversal causes denial of service via deep dependency chains

- **ID**: CVE\-2026\-129225 / GHSA\-xfcv\-m889\-fmqg
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Root Cause The dependency\-graph traversal helpers recurse over dependency links without any depth bound or visited set\. \`DependencyGraph\.\_tree\` \(\`nltk/parse/dependencygraph\.py\:404\`\) recurses once per dependency link, \`triples\` \(\`nltk/parse/dependencygraph\.py\:432\`\) is a recursive generator, and \`get\_cycle\_path\` \(\`nltk/parse/dependencygraph\.py\:520\`\) recurses over dependencies\. The neighbouring \`contains\_cycle\` method was deliberately rewritten as an iterative depth\-first search, but these sibling helpers on the public traversal path were left recursive with no depth counter\. \#\# Impact An appl
