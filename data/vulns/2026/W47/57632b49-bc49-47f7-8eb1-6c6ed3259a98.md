# Timezone cache use\-after\-free can lead to remote code execution\.

- **ID**: CVE\-2026\-129496
- **危険度**: Critical（緊急） (CVSS 9.2)
- **言語**: PHP
- **公開**: 2026-11-19

## 原文

Timezone cache use\-after\-free can lead to remote code execution\.
  
In non\-thread\-safe builds, a diagnostic written to a file\-based error\_log during module startup, for example for an invalid date\.timezone value or a session configuration warning, causes the timezone cache to be allocated in startup memory that is freed while a reference to it is kept\. A diagnostic raised early in the first request of a worker, such as the max\_input\_vars warning, then accesses the freed cache\. On such a deployment an unauthenticated remote attacker can crash PHP\-FPM, Apache mod\_php or CGI workers with a crafted request\. Arbitrary code execution may be possible and has been demonstrated with known memory addresses\.
  
This issue affects PHP versions before 8\.2\.36, 8\.3\.\* before 8\.3\.37, 8\.4\.\* before 8\.4\.28 and 8\.5\.\* before 8\.5\.13\.
