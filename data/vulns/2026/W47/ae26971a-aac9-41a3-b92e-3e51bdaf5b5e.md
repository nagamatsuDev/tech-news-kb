# NLTK\: Downloader cyclic collection indices cause an infinite closure walk

- **ID**: CVE\-2026\-128140 / GHSA\-pcm8\-fqjx\-rvx8
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.6\.7, &lt; 3\.10\.4 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

&gt; \*\*affected\*\*\: PyPI \`nltk\` \`&gt;\= 3\.6\.7\` — \`nltk\.downloader\` index parsing \(\`Downloader\.\_update\_index\`\) &gt; \*\*dynamically reproduced\*\*\: \`nltk\` \`3\.6\.7\` \(4/4 checks\), \`3\.9\.2\` \(4/4\), \`3\.10\.3\` \(4/4\), and \`develop\` \`6818767b9\` \(4/4\) \-\-\- \_Source references \(\`nltk/downloader\.py\:NNN\`\) are to commit \`6818767b9\` \(\`develop\`, \`v3\.10\.3\-15\-g6818767b9\`\)\. The \`v3\.10\.3\` tag and the released \`3\.10\.3\` wheel carry the identical code at the identical line numbers \(the vulnerable closure BFS sits at \`downloader\.py\:1300\-1310\`\)\. Dynamically verified wheels additionally show the same defect at \`downloader\.py\:972\` \(\`3\.9\.2\`
