# In the Linux kernel, the following vulnerability has been resolved\: KVM\: guest\_memfd\: take the invalidate lock when unbinding a dying fi\.\.\.

- **ID**: CVE\-2026\-99336
- **危険度**: High（重要） (CVSS 7.0)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
KVM\: guest\_memfd\: take the invalidate lock when unbinding a dying file
  
kvm\_gmem\_unbind\(\) takes mapping\-&gt;invalidate\_lock only if the  
get\_file\_active\(\) succeeds\. When the guest\_memfd file is dying, its  
reference count is already zero so get\_file\_active fails and the binding  
is removed without holding the invalidate lock\.
  
kvm\_gmem\_invalidate\_\{start,end\}\(\) checks f\-&gt;bindings independently to  
decide whether to begin or end KVM MMU invalidation\. So, the bindings  
must therefore remain stable between the two calls\. Otherwise, unbind  
can remove a binding after start increments mmu\_invalidate\_in\_progress,  
but before end finds the binding and decrements it\.  
Example, unbind race with memory failure\:
  
  CPU 0\: memory failure               CPU 1\: memslot delete  
  \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-  \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-  
                                      \(guest\_memfd file is dying\)  
  kvm\_gmem\_error\_folio\(\)  
    kvm\_gmem\_invalidate\_start\(\)  
      finds binding  
      mmu\_invalidate\_in\_progress\+\+  
                                      kvm\_gmem\_unbind\(\)  
                                        get\_file\_active\(\) fails  
                                        removes binding  
    kvm\_gmem\_invalidate\_end\(\)  
      no binding found  
      counter stays elevated
  
mmu\_invalidate\_retry\(\) then returns 1 forever, so guest page faults  
retry without ever installing a mapping and the guest hangs\.
  
Remove the distinction between live and dying files in the unbind path\.  
Always use slot\-&gt;gmem\.file and take the invalidate lock when it's non\-NULL\.  
Normal unbind callers hold slots\_lock, which prevents release from clearing  
the pointer or freeing the file state until unbind completes\. Final VM  
teardown can only see a NULL pointer because guest\_memfd pins the KVM until  
release has cleared all bindings\.
