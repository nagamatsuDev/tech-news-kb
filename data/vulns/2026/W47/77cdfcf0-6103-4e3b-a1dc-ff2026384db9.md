# In the Linux kernel, the following vulnerability has been resolved\: nvmet\-auth\: serialize access to DH\-HMAC\-CHAP state to fix UAF A REP\.\.\.

- **ID**: CVE\-2026\-99441
- **危険度**: High（重要） (CVSS 8.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
nvmet\-auth\: serialize access to DH\-HMAC\-CHAP state to fix UAF
  
A REPLY AUTH\_SEND command can derive a dhchap\_skey key while a  
concurrent AUTH\_RECEIVE command observing this REPLY state executes  
the failure path and frees that key\. The REPLY command then continues  
and writes into freed memory, causing a use\-after\-free\. KASAN reports  
it as\:
  
  BUG\: KASAN\: slab\-use\-after\-free in \_\_sha256\_final  
  Write of size 4 at addr ffff88800359c540  
  \.\.\.  
  nvmet\_auth\_sq\_free \(drivers/nvme/target/auth\.c\:237\)  
  nvmet\_execute\_auth\_receive \(drivers/nvme/target/fabrics\-cmd\-auth\.c\:621\)
  
Add a mutex to each submission queue to serialize authentication  
commands and timeout handling\. Unlock the mutex before completing  
requests and ignore outdated timeout callbacks\. Limit timeout delays  
to prevent immediate expiry on 32\-bit kernels\.
