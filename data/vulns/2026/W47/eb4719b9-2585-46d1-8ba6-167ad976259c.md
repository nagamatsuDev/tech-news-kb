# NLTK\: Uncontrolled recursion in CCG lexicon parser causes denial of service via deeply nested category input

- **ID**: CVE\-2026\-129224 / GHSA\-3h95\-x772\-4765
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Root Cause The CCG lexicon parser recurses on nested parenthesised categories without any depth bound\. \`matchBrackets\` \(\`nltk/ccg/lexicon\.py\:154\`\) calls itself once per nested \`\(\`, and \`augParseCategory\` \(\`nltk/ccg/lexicon\.py\:228,242\`\) recurses once per bracketed sub\-category\. Neither function tracks recursion depth nor checks \`sys\.getrecursionlimit\(\)\`, and the public entry point \`fromstring\` \(\`nltk/ccg/lexicon\.py\:252\`, also re\-exported via \`nltk\.ccg\.chart\.fromstring\`\) applies no length or nesting cap before handing the text to the parser\. \#\# Impact An application that parses an untrusted l
