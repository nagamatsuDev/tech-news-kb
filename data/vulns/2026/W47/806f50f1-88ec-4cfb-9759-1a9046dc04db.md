# Jupyter MCP Server\: Unauthenticated management routes can hijack the Jupyter backend in standalone HTTP mode

- **ID**: CVE\-2026\-77318 / GHSA\-24pw\-rf5p\-mgp7
- **危険度**: High（重要） (CVSS 7.3)
- **言語**: Python
- **パッケージ**: PyPI/jupyter\-mcp\-server &lt;\= 1\.0\.2 → 1\.0\.3
- **公開**: 2026-11-19

## 原文

Standalone \`streamable\-http\` mode in \`datalayer/jupyter\-mcp\-server\` requires \`MCP\_TOKEN\` for \`/mcp\`, but the custom management routes mounted on the same application do not enforce that token\. An unauthenticated network caller can invoke \`PUT /api/connect\`, choose the Jupyter backend URL and token fields, reset the server context, and make the MCP server start a kernel client against attacker\-controlled infrastructure\. The same missing authentication affects the state\-changing \`DELETE /api/stop\` route\. The intended authentication boundary is documented in the security guide and enforced during
