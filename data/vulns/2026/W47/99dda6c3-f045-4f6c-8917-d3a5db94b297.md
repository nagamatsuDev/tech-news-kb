# In the Linux kernel, the following vulnerability has been resolved\: mm/huge\_memory\: fix list corruption when deferred\_split\_scan\(\) races\.\.\.

- **ID**: CVE\-2026\-99728
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/huge\_memory\: fix list corruption when deferred\_split\_scan\(\) races with deferred\_split\_folio\(\)
  
Since the deferred split queue became a list\_lru, the isolate callback  
moves the folios it took a reference on to an on\-stack list, linked  
through folio\-&gt;\_deferred\_list, and deferred\_split\_scan\(\) takes them off  
that list with list\_del\_init\(\) without holding the list\_lru lock\.
  
deferred\_split\_folio\(\) does not know about the on\-stack list\. It only  
holds the list\_lru lock when it looks at the same list\_head, and it can  
run for such a folio\: a THP is queued when it is mapped, as a candidate  
for the underused check, and is queued "again" when a part of it gets  
unmapped\:
  
  CPU0 deferred\_split\_scan\(\)          CPU1 deferred\_split\_folio\(\)  
  list\_del\_init\(&amp;folio\-&gt;\_deferred\_list\)  
    next\-&gt;prev \= prev  
    prev\-&gt;next \= next  
    entry\-&gt;next \= entry  
                                      list\_lru\_lock\_irqsave\(\)  
                                      folio\_set\_partially\_mapped\(\)  
                                      \_\_list\_lru\_add\(\)  
                                        list\_empty\(item\)  \-&gt; true  
                                        list\_add\_tail\(item, &amp;l\-&gt;list\)  
                                          item\-&gt;next \= &amp;l\-&gt;list  
                                          item\-&gt;prev \= tail  
    entry\-&gt;prev \= entry
  
The folio now sits on the list\_lru with \-&gt;prev pointing to itself\. The  
next removal leaves the neighbours pointing to it, and they still do so  
after the folio has been freed\. With CONFIG\_DEBUG\_LIST\:
  
  list\_del corruption\. prev\-&gt;next should be ffd4000000270090, but was  
  ffd4000000278090\. \(prev\=ffd4000000270090\)
  
Fix it by grabbing the lock around list\_del\_init\(\) so  
deferred\_split\_folio\(\) cannot race with it\.
