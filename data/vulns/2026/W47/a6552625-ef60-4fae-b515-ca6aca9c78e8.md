# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: do not pass a NULL buf to is\_oplock\_break\(\) receive\_en\.\.\.

- **ID**: CVE\-2026\-99549
- **危険度**: High（重要） (CVSS 7.5)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: do not pass a NULL buf to is\_oplock\_break\(\)
  
receive\_encrypted\_read\(\) sets \*num\_mids \= 1 and never writes the  
caller's bufs\[\]\. Offload returns \-1 with \*num\_mids \= 0, so the  
demultiplex thread skips the frame\. The inline decrypt path  
returns 0 even when smb2\_find\_mid\(\) fails\.
  
cifs\_demultiplex\_thread\(\) then treats mids\[i\] \=\= NULL as an  
oplock break and calls is\_oplock\_break\(bufs\[i\], server\) with  
bufs\[i\] still NULL\. smb2\_is\_valid\_oplock\_break\(\) reads  
hdr\.Command at offset 12 and oopses\.
  
A large encrypted READ whose MessageId does not match is enough  
to panic cifsd\.
  
    Oops\: general protection fault, probably for non\-canonical address  
    0xdffffc0000000001\: 0000 \[\#1\] SMP KASAN PTI  
    KASAN\: null\-ptr\-deref in range  
    \[0x0000000000000008\-0x000000000000000f\]  
    CPU\: 0 PID\: 100 Comm\: cifsd  
    RIP\: smb2\_is\_valid\_oplock\_break\+0xc8/0x2270 \[cifs\]  
    cifs\_demultiplex\_thread  
    Kernel panic \- not syncing\: Fatal exception
  
Return \-1 when inline decrypt finds no mid, and skip  
is\_oplock\_break\(\) plus the unknown\-frame dump when bufs\[i\]  
is NULL\. receive\_encrypted\_standard\(\) already assigns  
bufs\[\*num\_mids\]\.
