# mail\-parser\: Uncaught exceptions and silent header loss in mail\-parser on attacker\-controlled input

- **ID**: CVE\-2026\-129299 / GHSA\-24mq\-4vc6\-2prf
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: Python
- **パッケージ**: PyPI/mail\-parser &lt;\= 4\.6\.1 → 4\.6\.2
- **公開**: 2026-11-16

## 原文

\#\#\# Impact Two effects, sharing the root cause of Advisory 1 — header names chosen by the sender were resolved through Python attribute lookup and rewritten before lookup\. \*\*Uncaught exceptions\.\*\* A crafted message raises an exception that is \*outside\* the \`MailParser\*\` hierarchy, so a caller catching only mail\-parser exceptions does not catch it and the worker dies\. \*Header named after a method\* \(CWE\-248, reported by @iam\-niranjan\)\. Python resolves real class attributes before \`\_\_getattr\_\_\`, so a header named after a method put a bound method object into the parsed mail dict\. A 12\-byte email
