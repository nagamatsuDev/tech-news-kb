# In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the mc\_investigation\_read capability could inject arbit\.\.\.

- **ID**: CVE\-2026\-131218
- **危険度**: High（重要） (CVSS 8.3)
- **公開**: 2026-11-19

## 原文

In Splunk Enterprise Security versions below 8\.7\.0, a user that holds a role with the mc\_investigation\_read capability could inject arbitrary Search Processing Language \(SPL\) into Mission Control dashboard search requests\. Mission Control could then run the injected SPL with elevated permissions\. With this access, the user could cause Mission Control to read stored credentials and write data to indexes and lookups\.  
The vulnerability is possible because Mission Control does not validate reserved search filters before adding them to dashboard searches\.  
For more information see Overview of Mission Control in Splunk Enterprise Security \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/user\-guide/8\.1/mission\-control/overview\-of\-mission\-control\-in\-splunk\-enterprise\-security\) and Capability reference for Splunk Enterprise Security \(https\://help\.splunk\.com/en/splunk\-enterprise\-security\-8/install/8\.2/installation/capability\-reference\-for\-splunk\-enterprise\-security\) in the Splunk documentation\.
