# In the Linux kernel, the following vulnerability has been resolved\: mptcp\: do not use Fast Open on MP\_JOIN subflows tcp\_fastopen\_create\.\.\.

- **ID**: CVE\-2026\-99634
- **危険度**: Critical（緊急） (CVSS 9.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mptcp\: do not use Fast Open on MP\_JOIN subflows
  
tcp\_fastopen\_create\_child\(\) hands the SYN packet itself to  
subflow\_syn\_recv\_sock\(\)\. For an MP\_JOIN request this takes the  
fatal fallback\: the cloned child is destroyed and handed back with  
drop\_req flagged, but tcp\_fastopen\_create\_child\(\) does not check  
the flag and queues it, so accept\(\) can expose the freed child\.
  
MP\_JOIN cannot use Fast Open\: data on a subflow requires the  
completed HMAC exchange \(RFC 8684, sec\. 3\.2\)\. Refuse it \(only the  
TFO path passes a SYN skb here\) and let tcp\_conn\_request\(\) fall  
back to the regular MP\_JOIN handshake; also strip the Fast Open  
cookie from MP\_JOIN SYN/ACKs\.
  
\[ Moving code to avoid clearing TS and consolidating checks\. \]
