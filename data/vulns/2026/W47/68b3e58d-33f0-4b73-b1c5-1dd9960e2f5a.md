# In the Linux kernel, the following vulnerability has been resolved\: mm\: memcontrol\: fix NULL pointer deref and UAF from high\_work\_func\(\)\.\.\.

- **ID**: CVE\-2026\-99697
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm\: memcontrol\: fix NULL pointer deref and UAF from high\_work\_func\(\) on dying memcg
  
When memory\.high is exceeded in non\-task context, try\_charge\_memcg\(\)  
schedules memcg\-&gt;high\_work without taking a reference on the memcg, and  
high\_work\_func\(\) invokes reclaim\_high\(\) without pinning the memcg\.
  
With obj\_cgroup reparenting, introduced in commit bf4f059954dc \("mm\:  
memcg/slab\: obj\_cgroup API"\), objects charged to a child memcg are  
reparented to its parent in mem\_cgroup\_css\_offline\(\) instead of holding a  
reference on the child until uncharged\.  Subsequent uncharges of those  
objects go to the parent, which can leave the child's memory use  
permanently above its high limit, so any later charge on the offlined  
memcg in non\-task context schedules high\_work\.  This was later widened  
from kernel memory to LRU folios when commit f1cf8d2f36dc \("mm\:  
memcontrol\: eliminate the problem of dying memory cgroup for LRU folios"\)  
converted LRU folios to use obj\_cgroup reparenting\.
  
cancel\_work\_sync\(&amp;memcg\-&gt;high\_work\) only runs at the end of teardown in  
mem\_cgroup\_css\_free\(\), so high\_work\_func\(\) can start or still be running  
reclaim\_high\(\) after mem\_cgroup\_css\_released\(\) or shrink\_many\(\) has called  
lru\_gen\_release\_memcg\(\) and unhashed lruvec\-&gt;lrugen\.list\.  If reclaim  
tries to rotate the memcg, lru\_gen\_rotate\_memcg\(\) dereferences a NULL  
pprev pointer\.  This issue is specific to MGLRU and was introduced with  
the memcg LRU in commit e4dde56cd208 \("mm\: multi\-gen LRU\: per\-node  
lru\_gen\_folio lists"\)\.
  
With either traditional LRU or MGLRU, css\_free\_rwork\_fn\(\) calls  
css\_rstat\_exit\(\) which frees per\-CPU rstat data before calling  
mem\_cgroup\_css\_free\(\)\.  If reclaim\_high\(\) is still running, rstat updates  
via mod\_lruvec\_state\(\) \-&gt; \_\_css\_rstat\_updated\(\) cause a use\-after\-free on  
the per\-CPU rstat data\.  This was introduced when commit 5da3bfa029d6  
\("cgroup\: use separate rstat trees for each subsystem"\) moved  
css\_rstat\_exit\(\) ahead of ss\-&gt;css\_free\(\)\.
  
Fix both problems by acquiring a reference with css\_tryget\_online\(\) in  
high\_work\_func\(\) before calling reclaim\_high\(\), and by resetting  
memory\.high and swap\.high to PAGE\_COUNTER\_MAX in mem\_cgroup\_css\_offline\(\)  
so that charges via references on an offlined memcg do not trigger  
high\_work on the dead child and skip checking live ancestors in  
try\_charge\_memcg\(\)\.
  
Acquiring the reference in high\_work\_func\(\) rather than before scheduling  
high\_work is safe because mem\_cgroup\_css\_free\(\) calls irq\_work\_sync\(\) and  
cancel\_work\_sync\(\) which cancels pending work and waits for an already  
running high\_work\_func\(\) to complete before mem\_cgroup\_free\(\) frees the  
memcg\.  css\_tryget\_online\(\) uses percpu\_ref\_tryget\_live\(\) and is safe to  
call after percpu\_ref\_exit\(\) before the cgroup is freed unlike  
css\_tryget\(\)\.
