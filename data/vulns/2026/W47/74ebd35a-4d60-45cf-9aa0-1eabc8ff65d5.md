# In the Linux kernel, the following vulnerability has been resolved\: filelock\: keep superblock active through delegation wait A caller m\.\.\.

- **ID**: CVE\-2026\-99478
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
filelock\: keep superblock active through delegation wait
  
A caller may drop its path after try\_break\_deleg\(\) returns a delegated  
inode but before break\_deleg\_wait\(\) finishes\. The extra inode reference  
held in struct delegated\_inode does not keep the superblock active\.
  
After a lazy unmount, closing the delegation holder can release the last  
mount reference and shut down the superblock while another task waits for  
the delegation break\. The waiter's final iput\(\) can then enter the  
filesystem's eviction code after its superblock\-private state was freed\.  
This has been observed as a KASAN use\-after\-free in shmem\_evict\_inode\(\)\.
  
When try\_break\_deleg\(\) saves a delegated inode, take an active reference  
to its superblock while the caller still pins the mount\. Keep that  
reference through break\_deleg\_wait\(\) and the final iput\(\), then release  
it with deactivate\_super\(\)\. This protects every caller of the helpers,  
including the mknod, mkdir, symlink and rmdir paths that drop their path  
before waiting\.
