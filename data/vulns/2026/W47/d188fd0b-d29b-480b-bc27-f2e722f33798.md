# NLTK incomplete fix\: additional JVM/JAR sandbox bypass through unvalidated launcher tokens in java\(\) command arguments

- **ID**: CVE\-2026\-128138 / GHSA\-x8q7\-6c7m\-52gw
- **危険度**: Critical（緊急） (CVSS 9.8)
- **言語**: Python, Java/Kotlin
- **パッケージ**: PyPI/nltk &gt;\= 3\.10\.3, &lt; 3\.10\.4 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Summary NLTK 3\.10\.3 contains security hardening intended to close JVM argument\-injection and untrusted JAR/classpath execution paths in \`nltk\.internals\.java\(\)\`, including the issue published as GHSA\-m4rf\-3fr8\-xwx3\. The patched \`options\` channel correctly rejects Java argument\-file references such as \`@/path/to/args\` and launcher modes such as \`\-jar\`\. However, an additional argument channel remains\: the caller\-provided \`cmd\` sequence is appended to the Java command after the validated option and classpath channels, without enforcing that its first item is a Java main\-class name\.
