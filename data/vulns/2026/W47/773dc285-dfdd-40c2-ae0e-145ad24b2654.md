# In the Linux kernel, the following vulnerability has been resolved\: mm/mglru\: don't use stack pointers when walking PUD and PMD tables \.\.\.

- **ID**: CVE\-2026\-99735
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/mglru\: don't use stack pointers when walking PUD and PMD tables
  
MGLRU passes stack copies of page\-table entries in walk\_pud\_range\(\) and  
walk\_pmd\_range\(\) when walking to the next level\. These copies can become  
stale when khugepaged or MADV\_DONTNEED \(CONFIG\_PT\_RECLAIM\) removes a PTE  
table concurrently\.
  
This pattern dates back to commit bd74fdaea146 \("mm\: multi\-gen LRU\:  
support page table walks"\)\. Likely, earlier locking masked the latent  
bug\. Later changes exposed it\: commit 1d65b771bc08 \("mm/khugepaged\:  
retract\_page\_tables\(\) without mmap or vma lock"\) allowed concurrent  
retraction, and commit cf4a65539c13 \("memcg\-v1\: no need for memcg locking  
for MGLRU"\) dropped the walker's outer RCU protection\.
  
The fix is simple, so just fix the original commit so we don't have to  
speculate\. To fix it, pass the actual PMD/PUD pointers\. This restores the  
RCU\-protected lookup and validation against the live PMD\. Note that the PUD  
handling is required as well to handle folded page tables correctly in all  
cases\.
  
Fix generated by an LLM and sent by Josef Bacik in private\.
  
\[ david\: handle walk\_pud\_range\(\) as well, clarify\+simplify description,  
         adjust Fixes\: \]
