# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: reclaim credits for decrypted reads with no matching mi\.\.\.

- **ID**: CVE\-2026\-99383
- **危険度**: High（重要） (CVSS 7.5)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: reclaim credits for decrypted reads with no matching mid
  
When a decrypted SMB2 READ response carries a MessageId that matches no  
outstanding request, both the inline receive\_encrypted\_read\(\) and the  
offloaded smb2\_decrypt\_offload\(\) paths drop the frame without accounting  
the credits the server granted in it\.  The plaintext unknown\-frame path in  
cifs\_demultiplex\_thread\(\) already reclaims them with  
smb2\_add\_credits\_from\_hdr\(\), so encrypted reads leak credits that the  
plaintext path would not\.
  
This also happens for legitimate frames \- e\.g\. a reply that arrives after  
the client has timed out and dropped the mid \- so over a long\-lived  
connection the client's credit count drifts down and can eventually starve  
it of the ability to issue requests\.  The frame is AEAD\-authenticated, so  
the granted credits in the decrypted header come from the real server and  
are safe to apply\.
  
Reclaim the credits from the decrypted header before dropping the frame,  
and export smb2\_add\_credits\_from\_hdr\(\) so the SMB2 receive paths can use it\.
