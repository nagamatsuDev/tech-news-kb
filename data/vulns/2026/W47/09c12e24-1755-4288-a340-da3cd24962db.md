# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: fix buffer overflow in SMB2\_tcon\(\) In SMB2\_tcon\(\), unc\.\.\.

- **ID**: CVE\-2026\-99385
- **危険度**: Critical（緊急） (CVSS 9.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: fix buffer overflow in SMB2\_tcon\(\)
  
In SMB2\_tcon\(\), unc\_path is allocated with a fixed buffer size of  
MAX\_SHARENAME\_LENGTH \* 2 bytes \(672 bytes\)\. However, the user\-controlled  
UNC path \(tree\) length is passed to cifs\_strtoUTF16\(\), which assumes the  
destination buffer is large enough and writes strlen\(tree\) \+ 1 UTF\-16 code  
units\.
  
Commit 62a1a439e0fd \("cifs\: clean up handling of unc\= option"\) removed the  
length check on UNC mount options, allowing mount paths to exceed  
MAX\_SHARENAME\_LENGTH while retaining the fixed\-size buffer allocation in  
SMB2\_tcon\(\)\. Consequently, an oversized UNC string causes cifs\_strtoUTF16\(\)  
to write past the end of the heap object, resulting in a slab\-out\-of\-bounds  
write\. Furthermore, if a tree exceeds MAX\_TREE\_SIZE characters, strscpy\(\)  
truncates it in cifs\_tcon\:\:tree\_name, causing subsequent reconnects or  
failovers to fail\.
  
Fix this by first verifying that the length of tree does not exceed  
MAX\_TREE\_SIZE, returning \-EINVAL if it does\. Then, dynamically allocate  
unc\_path based on the length of tree so that it safely accommodates all  
UTF\-16 code units for paths within MAX\_TREE\_SIZE\.
  
\[pc\: remove unused MAX\_SHARENAME\_LENGTH\]
