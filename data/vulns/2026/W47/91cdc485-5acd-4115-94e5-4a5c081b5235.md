# In the Linux kernel, the following vulnerability has been resolved\: io\_uring\: defer foreign io\-wq enqueues to task\_work An IOPOLL ring \.\.\.

- **ID**: CVE\-2026\-99798
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
io\_uring\: defer foreign io\-wq enqueues to task\_work
  
An IOPOLL ring without DEFER\_TASKRUN can be reaped by a task other than  
the one that submitted the I/O\. If a polled request is marked  
REQ\_F\_REISSUE, io\_free\_batch\_list\(\) calls io\_queue\_iowq\(\) with the  
original tctx\. Ordinary task exit can tear down tctx\-&gt;io\_wq after  
draining only the tracked requests\. The live request pins the task, but  
not its io\-wq, so the foreign task can race io\_wq\_put\_and\_exit\(\) and  
enqueue through a freed or NULL queue\.
  
Forward foreign userspace enqueues to the owning task before accessing  
tctx\-&gt;io\_wq\. Use a dedicated task\_work callback so reissues still go  
straight to io\-wq, and fail them if task\_work is running in cancellation  
mode\. Preserve the existing PF\_KTHREAD cancellation path\. This also  
covers the other callers of io\_queue\_iowq\(\) without changing the  
worker\-owned enqueue path\.
