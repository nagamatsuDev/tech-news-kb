# In the Linux kernel, the following vulnerability has been resolved\: io\_uring\: free the task context after a grace period A task other t\.\.\.

- **ID**: CVE\-2026\-99800
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
io\_uring\: free the task context after a grace period
  
A task other than the owner can free a request, io\_ring\_exit\_work\(\)  
running the local task\_work of a DEFER\_TASKRUN ring for example, or  
io\_do\_iopoll\(\) reaping completions\. io\_put\_task\(\) then takes the else  
branch\:
  
    percpu\_counter\_sub\(&amp;tctx\-&gt;inflight, 1\);  
    if \(unlikely\(atomic\_read\(&amp;tctx\-&gt;in\_cancel\)\)\)  
            wake\_up\(&amp;tctx\-&gt;wait\);  
    put\_task\_struct\(tctx\-&gt;task\);
  
The first line is what lets the owner leave io\_uring\_cancel\_generic\(\),  
and on exec it frees the tctx right after\. Nothing holds that off for  
the remaining three lines, the task reference only covers a tctx freed  
along with the task\_struct\. It used to work out because  
io\_uring\_del\_tctx\_node\(\) took the uring\_lock that the freeing side holds  
across io\_put\_task\(\), until that moved to tctx\_lock\.
  
Free the tctx with kfree\_rcu\(\), and enter an RCU read section in  
io\_put\_task\(\) before the count is dropped\.
