# NLTK\: Untrusted search path in prover9/mace4 config allows local code execution via relative binary\_location

- **ID**: CVE\-2026\-129234 / GHSA\-cc5r\-64rf\-75hg
- **危険度**: High（重要） (CVSS 7.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-19

## 原文

\#\# Summary \`Prover9Parent\.config\_prover9\(binary\_location\=\.\.\.\)\` \(and \`Mace\`, which inherits it\) accepts a relative \`binary\_location\` and passes it as \`path\_to\_bin\` to \`find\_binary\`, which disables the CWD\-relative rejection guard\. Unlike the boxer/senna/malt/repp siblings, prover9/mace apply no \`os\.path\.isabs\(\)\` filter, so the resolved relative program path \(e\.g\. \`\./prover9\`\) is executed from the current working directory via \`subprocess\.Popen\`\. A local attacker who can plant \`\./prover9\` \(or \`\./mace4\`\) in the resolved directory achieves local code execution\. \#\# Root Cause \`nltk/inference/prover
