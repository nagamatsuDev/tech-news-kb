# obsidian\-sync\-mcp\: Missing Host/Origin validation lets a public website drive a victim's Obsidian vault via DNS rebinding \(no\-auth mode\)

- **ID**: CVE\-2026\-77283 / GHSA\-mx6p\-3fg7\-v6pj
- **危険度**: High（重要） (CVSS 8.8)
- **言語**: JavaScript/TypeScript
- **パッケージ**: npm/obsidian\-sync\-mcp &lt;\= 0\.5\.6 → 0\.5\.7
- **公開**: 2026-11-18

## 原文

When obsidian\-sync\-mcp runs without MCP\_AUTH\_TOKEN \(the documented no\-auth mode for local use\), the HTTP MCP endpoint does not validate the Host or Origin header before dispatching MCP methods \(CWE\-350\)\. The no\-auth mode's "local network only" assumption therefore does not hold\: a malicious web page the operator visits can use DNS rebinding to resolve an attacker\-controlled hostname to 127\.0\.0\.1 \(or the operator's LAN/VPN/Docker\-published address\) and issue requests the server accepts as trusted local calls, reaching the full tool surface \(read\_note, write\_note, edit\_note, delete\_note, move\_no
