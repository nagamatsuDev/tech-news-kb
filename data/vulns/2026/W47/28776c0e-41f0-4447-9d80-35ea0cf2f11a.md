# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: don't resurrect an exiting tcon from cached dir workers\.\.\.

- **ID**: CVE\-2026\-99386
- **危険度**: High（重要） (CVSS 7.5)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: don't resurrect an exiting tcon from cached dir workers
  
cfids\_laundromat\_worker\(\) bumps tcon\-&gt;tc\_count for every expired open  
cfid and queues cached\_dir\_offload\_close\(\) without checking whether the  
tcon is already being torn down\.  Racing with the final cifs\_put\_tcon\(\),  
the tcon comes back from zero and gets torn down twice\:
  
  T1                                  T2  
  cifs\_put\_tcon\(\)  
   \-\-tc\_count \=\= 0, TID\_EXITING  
   tconInfoFree\(\)  
    free\_cached\_dirs\(\)  
     cancel\_delayed\_work\_sync\(\)       cfids\_laundromat\_worker\(\)  
                                       \+\+tc\_count \=\= 1  
                                       queue\_work\(serverclose\_wq\)  
    kfree\(tcon\-&gt;origin\_fullpath\)  
    kfree\(tcon\)  
                                      cached\_dir\_offload\_close\(\)  
                                       close\_cached\_dir\(\)  \[UAF\]  
                                       cifs\_put\_tcon\(\)  
                                        tconInfoFree\(\)     \[double free\]
  
cached\_dir\_lease\_break\(\) also bumps tc\_count without tc\_lock, racing with  
the laundromat's locked update\.
  
Take the tcon reference through a helper that refuses once the tcon is  
TID\_EXITING or its refcount has dropped to zero\.  Queued put\_work and  
close\_work then always hold a tcon reference, so tconInfoFree\(\) can't  
run before they finish and free\_cached\_dirs\(\) doesn't need to flush any  
workqueue\.  If the laundromat can't get a reference, put the cfid back on  
the dying list for free\_cached\_dirs\(\) to free; its handle goes away with  
the tree connection\.
  
The lease break path finds the tcon on ses\-&gt;tcon\_list under  
cifs\_tcp\_ses\_lock, so it can't see TID\_EXITING, but it now takes tc\_lock\.
