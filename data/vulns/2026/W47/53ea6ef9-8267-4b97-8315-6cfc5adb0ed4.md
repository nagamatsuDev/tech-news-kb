# In the Linux kernel, the following vulnerability has been resolved\: RDMA/uverbs\: Fix DMABUF use\-after\-free during ufile cleanup The DMA\.\.\.

- **ID**: CVE\-2026\-99523
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
RDMA/uverbs\: Fix DMABUF use\-after\-free during ufile cleanup
  
The DMABUF release can race with ufile cleanup\. When the cleanup holds  
hw\_destroy\_rwsem for write, uverbs\_uobject\_release\(\) fails its trylock  
and leaves the uobject on the ufile list, but the dma\_buf is freed as  
soon as the release returns\. The cleanup then destroys the uobject and  
uses the freed dma\_buf\:
  
  BUG\: KASAN\: slab\-use\-after\-free in uverbs\_dmabuf\_fd\_destroy\_uobj\+0x46/0x200  
  Read of size 8 at addr ff11000109cf14b0 by task repro/435  
  Call Trace\:  
   uverbs\_dmabuf\_fd\_destroy\_uobj\+0x46/0x200  
   destroy\_hw\_fd\_uobject\+0x3f/0x50  
   uverbs\_destroy\_uobject\+0xc5/0x380  
   \_\_uverbs\_cleanup\_ufile\+0x1a8/0x260  
   uverbs\_destroy\_ufile\_hw\+0x54/0x160  
   ib\_uverbs\_close\+0x34/0x110  
  Allocated by task 435\:  
   dma\_buf\_export\+0x1b5/0x530  
   ib\_uverbs\_handler\_UVERBS\_METHOD\_DMABUF\_ALLOC\+0x223/0x3f0  
  Freed by task 436\:  
   kfree\+0x301/0x530  
   dentry\_kill\+0x14c/0x560  
   \_\_fput\+0x23a/0x4a0
  
rdma\_user\_mmap\_entry\_remove\(\) dereferences the same pointer\.
  
Protect the stored dma\_buf pointer with a mutex and clear it before  
release returns\. Use a shared revoke helper so uobject destruction and  
mmap entry removal both skip a cleared pointer\. Hold a temporary uobject  
reference across uverbs\_uobject\_release\(\) and the pointer update\.
  
Use a separate mutex because uobject destruction can free the mmap entry  
before release finishes\. Map and unmap use attachment\-&gt;dmabuf directly,  
so they do not need to take the new mutex while holding the reservation  
lock\.
