# In the Linux kernel, the following vulnerability has been resolved\: mm/cma\: don't release CMA pages still in use When a driver calls dm\.\.\.

- **ID**: CVE\-2026\-99645
- **危険度**: High（重要） (CVSS 7.0)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/cma\: don't release CMA pages still in use
  
When a driver calls dma\_free\_contiguous\(\) before quiescing DMA, the  
page might still have a reference from the device\.  
put\_page\_testzero\(\) there returns false, WARN fires, but the code proceeds  
to free\_contig\_frozen\_range\(\) putting a live page onto buddy and clearing  
the bitmap\. A subsequent allocation can hand the same PFN to a new  
owner while the original holder still references it\.
  
A concurrent put\_page\(\) that drops the last reference between the  
testzero loop and free\_contig\_frozen\_range\(\) can double\-queue the page  
via page\-&gt;lru, corrupting buddy lists\.
  
Avoid the corruption by not freeing a CMA region if any of the  
pages inside are still in use\.
  
Make it explicit in the warning that the driver allowed a leak\.
  
While at it, use page\_ref\_freeze\(\) to make the semantics clearer and  
switch to pr\_warn\_ratelimited\(\)\.
  
\[ david\: use page\_ref\_freeze\(\) \+ pr\_warn\_ratelimited\(\) \]
