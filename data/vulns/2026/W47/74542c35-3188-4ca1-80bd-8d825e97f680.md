# In Dolibarr before 24\.0\.3, dolForgeSQLCriteriaCallback\(\) in htdocs/core/lib/functions\.lib\.php allows account takeover because it strips o\.\.\.

- **ID**: CVE\-2026\-133476
- **危険度**: High（重要） (CVSS 8.8)
- **言語**: PHP
- **公開**: 2026-11-19

## 原文

In Dolibarr before 24\.0\.3, dolForgeSQLCriteriaCallback\(\) in htdocs/core/lib/functions\.lib\.php allows account takeover because it strips only a single table\-name prefix from a Universal Search Filter \(sqlfilters\) operand before checking it against the forbidden\-field denylist \(pass, pass\_crypted, api\_key\)\. MariaDB and MySQL accept a two\-level qualification such as schema\.alias\.column, so an operand of the form dolibarr\.u\.pass\_crypted survives the check and is emitted into the WHERE clause\. A remote authenticated user holding only the holiday read and readall permissions, which confer no user\-management or administrative access, can use the resulting boolean oracle at GET /api/index\.php/holidays to recover any user's bcrypt password hash and api\_key one character at a time, including an administrator's\. Because api\_key is accepted directly by the REST API as a bearer credential, this yields full administrative control of the application\. This bypasses the fix for CVE\-2026\-89012, which added only a strtolower\(\) call and did not address prefix depth\. The same denylist also omits pass\_temp, which stores a password in cleartext, as well as national\_registration\_number, salary, birth, address, personal\_mobile and note\_private\.
