# uu\_env incorrectly rejects backslashes within single\-quoted strings accepted by GNU env

- **ID**: CVE\-2026\-35377 / GHSA\-xhrc\-7f76\-vh96
- **危険度**: Low（注意） (CVSS 3.3)
- **言語**: Rust
- **パッケージ**: crates\.io/uu\_env &lt;\= 0\.9\.0 → 0\.10\.0
- **公開**: 2026-11-20

## 原文

In \`env \-S\`, GNU keeps backslashes literal inside single quotes \(except \`\\\\\` and \`\\'\`\); uutils errors on sequences like \`\\a\`\. This is the backslash\-handling issue of the broader \`\-S\`/\`\-\-split\-string\` parsing divergence\. \`\`\` env \-S"printf %s '\\''\\\\x'\\''" \# GNU prints \\x ; uutils\: invalid sequence '\\x' in \-S \(125\) \`\`\` \-\-\- \_Zellic private finding \(zellic\-ext/coreutils\-private PR \#117\)\. Reported in the Zellic \*uutils coreutils Program Security Assessment\* \(for Canonical, Jan 2026\), audited commit \`3a07ffc5a9bd4c283e75afa548ba1f1957bad242\`\.\_
