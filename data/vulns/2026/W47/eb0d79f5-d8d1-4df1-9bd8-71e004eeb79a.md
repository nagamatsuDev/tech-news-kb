# In the Linux kernel, the following vulnerability has been resolved\: mm/mmu\_gather\: fix flushing ranges with 4 GiB or larger \_\_tlb\_adjus\.\.\.

- **ID**: CVE\-2026\-99659
- **危険度**: High（重要） (CVSS 7.0)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
mm/mmu\_gather\: fix flushing ranges with 4 GiB or larger
  
\_\_tlb\_adjust\_range\(\) takes the size of the range which has to be flushed  
as an unsigned int\. Its callers, tlb\_flush\_\{pte,pmd,pud,p4d\}\_range\(\), get  
and pass an unsigned long\. Consequently, a range that is 4 GiB or larger  
gets truncated, possibly to 0\.
  
On arm64 with hugetlb, a 64k kernel can have 16 GiB hugetlb folios  
mapped contiguously at the PMD level and flush them when unmapping, and a  
16k kernel can flush 64 GiB PUDs through tlb\_unshare\_pmd\_ptdesc\(\)\. So  
at least these two scenarios are affected\.
  
Fix it by flushing the proper range instead of the truncated one by  
properly using "unsigned long" for range\_size\.
  
Fix generated by an LLM and sent by Josef Bacik in private\.
