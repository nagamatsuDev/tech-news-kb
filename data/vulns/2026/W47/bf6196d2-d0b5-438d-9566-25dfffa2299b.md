# sqlite\-mcp\: Read\-only mode bypass via statement chaining and SQL injection in describe\_table

- **ID**: CVE\-2026\-130008 / GHSA\-q433\-mp6c\-8v4f
- **危険度**: High（重要） (CVSS 8.2)
- **言語**: Go
- **パッケージ**: Go/github\.com/StacklokLabs/sqlite\-mcp &lt; 0\.1\.2 → 0\.1\.2
- **公開**: 2026-11-18

## 原文

\#\#\# Summary In read\-only mode \(the default\), a client that can call the MCP tools can write to the database the server is meant to expose read\-only, read other SQLite files, and create new SQLite files anywhere the server process can write\. There are two ways in\: statement chaining through \`execute\_query\`, and SQL injection through \`describe\_table\`\. \#\#\# Details \- \*\*Statement chaining in \`execute\_query\`\.\*\* The only check was that the query starts with \`SELECT\`\.
