# SharpIppNext\: Unbounded IPP Document Stream Buffering Leads to Denial of Service

- **ID**: CVE\-2026\-59975 / GHSA\-3h63\-w8jq\-rrf2
- **危険度**: High（重要） (CVSS 7.5)
- **言語**: C\#/\.NET
- **パッケージ**: NuGet/SharpIppNext &lt;\= 4\.0\.2 → 4\.1\.0
- **公開**: 2026-11-18

## 原文

\#\#\# Summary SharpIppNext's \`IppProtocol\.ReadIppRequestAsync\(\)\` unconditionally copies the entire attacker\-supplied IPP document payload into an unbounded \`MemoryStream\` with no size limit\. Because this behavior is enabled by default \(\`ReadDocumentStream \= true\`\) and the official server documentation shows \`HttpContext\.Request\.Body\` being passed directly to \`ReceiveRequestAsync\(\)\` without authentication, an unauthenticated remote attacker can exhaust the server process's memory by sending an arbitrarily large IPP request body, causing an Out\-Of\-Memory \(OOM\) condition and denial of service\. &gt; \[\!
