# In the Linux kernel, the following vulnerability has been resolved\: ksmbd\: serialize directory emptiness checks with readdir SMB2 QUERY\.\.\.

- **ID**: CVE\-2026\-99556
- **危険度**: High（重要） (CVSS 8.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ksmbd\: serialize directory emptiness checks with readdir
  
SMB2 QUERY\_DIRECTORY holds fp\-&gt;readdir\_lock while it calls iterate\_dir\(\)  
on fp\-&gt;filp\. An SMB2 SET\_INFO request with FILE\_DISPOSITION\_INFORMATION  
can resolve the same FileId and call ksmbd\_vfs\_empty\_dir\(\) on the same  
filp without that lock\.
  
iterate\_dir\(\)'s inode read lock permits concurrent readers and does not  
serialize per\-file iterator state\. ext4 stores its dx readdir cursor and  
fname RB tree in file\-&gt;private\_data\. Concurrent reset or refill can  
therefore free a fname node while the other worker still traverses it or  
retains its RB\-tree link, resulting in use\-after\-free accesses\.
  
An authenticated SMB client with list and delete rights on a directory in  
a writable KSMBD share backed by ext4 can trigger this when the directory  
takes the dx readdir path\. The client overlaps an SMB2 QUERY\_DIRECTORY  
request with an SMB2 SET\_INFO request carrying FILE\_DISPOSITION\_INFORMATION  
on one live FileId\.
  
In one x86\_64 SMP KASAN multi\-shot guest using ksmbd\-for\-next at  
171df27077fb, the unmodified kernel reported a cross\-worker use\-after\-free  
before a panic\. The first report's access and free stacks show the two  
request paths directly \(trimmed\)\:
  
  BUG\: KASAN\: slab\-use\-after\-free in ext4\_htree\_store\_dirent\+0x488/0x550  
  Read of size 8 by task kworker/2\:0/29  
  Workqueue\: ksmbd\-io handle\_ksmbd\_work  
  Call Trace\:  
   ext4\_htree\_store\_dirent\+0x488/0x550  
   htree\_dirblock\_to\_tree\+0x535/0x990  
   ext4\_htree\_fill\_tree\+0x319/0xba0  
   ext4\_readdir\+0x175a/0x2f40  
   iterate\_dir\+0x1b6/0x630  
   smb2\_query\_dir\+0x1003/0x1cc0
  
  Freed by task 279\:  
   free\_rb\_tree\_fname\+0x67/0xc0  
   ext4\_readdir\+0x13a9/0x2f40  
   iterate\_dir\+0x1b6/0x630  
   ksmbd\_vfs\_empty\_dir\+0xa2/0x100  
   smb2\_set\_info\+0x2ffa/0x45d0
  
Take fp\-&gt;readdir\_lock across the entire emptiness check\. This places both  
iterators over that handle's filp in the same lock domain while  
preserving the disposition status handling\. The exact code change  
completed a warning\-free x86\_64 KASAN bzImage build\. Tracing three request  
pairs showed that the two iterate\_dir\(\) calls no longer overlapped and the  
expected statuses were preserved\. A further 1,600 reproducer iterations  
completed with expected statuses and no KASAN report, Oops, or panic\.
  
The reproducer and complete guest configuration are available privately  
to maintainers on request\.
