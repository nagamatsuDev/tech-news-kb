# In the Linux kernel, the following vulnerability has been resolved\: ovl\: set OVL\_WHITEOUTS before publishing the upper dir Listing a di\.\.\.

- **ID**: CVE\-2026\-99424
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-19

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
ovl\: set OVL\_WHITEOUTS before publishing the upper dir
  
Listing a directory while it is copied up causes a use\-after\-free of  
the readdir cache\.
  
A merge directory must never be iterated as a real upper directory\:  
that mode frees the cache in OVL\_I\(inode\)\-&gt;cache without looking at  
its refcount, while files opened in merged mode still use it\.  
ovl\_copy\_up\_workdir\(\) publishes the upper dentry before it sets  
OVL\_WHITEOUTS, and ovl\_dir\_open\(\) samples both without a lock, so an  
open between the two stores finds the upper directory and takes it  
for a real one\.
  
With a delay between the two stores, an unprivileged process that  
listed a directory during its copy\-up saw only "\." and "\.\.", and its  
next getdents freed the readdir cache of another descriptor\.
  
Fix this by setting OVL\_WHITEOUTS before ovl\_inode\_update\(\), so that  
ovl\_dir\_reset\(\) agrees with ovl\_dir\_open\(\), and by testing  
OVL\_TYPE\_MERGE\(\) of the path type in ovl\_dir\_open\(\), so that an open  
that observes the upper dentry never iterates a merge dir as a real  
dir, regardless of the order in which it observes the flag\.
  
\[amir\: test OVL\_TYPE\_MERGE\(\) instead of smp\_rmb\(\) in ovl\_dir\_open\(\)\]
