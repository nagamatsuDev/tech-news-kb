# Nuxt\: Incomplete fix for GHSA\-6gq8\-jgmh\-3ffp\: an encoded slash \(\`%2F\`\) in the request path bypasses route rules on catch\-all page routes

- **ID**: CVE\-2026\-128071 / GHSA\-f3x9\-2chm\-73c8
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: JavaScript/TypeScript
- **パッケージ**: npm/nuxt &gt;\= 4\.0\.0, &lt; 4\.6\.4 → 4\.6\.4, npm/nuxt &gt;\= 3\.0\.0, &lt; 4\.0\.0, npm/@nuxt/nitro\-server &gt;\= 4\.2\.0, &lt; 4\.6\.4 → 4\.6\.4, npm/@nuxt/nitro\-server &gt;\= 3\.20\.0, &lt; 4\.0\.0, npm/@nuxt/vite\-server &gt;\= 4\.6\.0, &lt; 4\.6\.4 → 4\.6\.4
- **公開**: 2026-11-16

## 原文

\#\#\# Summary Nuxt matches route rules against the request path with encoded slashes \(\`%2F\`\) left encoded, while the page router decodes them into route params\. A request that spells a slash as \`%2F\` can therefore render a page through a catch\-all route without the route rules configured for the path it resolves to\. The fix for \[GHSA\-6gq8\-jgmh\-3ffp\]\(https\://github\.com/nuxt/nuxt/security/advisories/GHSA\-6gq8\-jgmh\-3ffp\) deliberately left reserved escapes such as \`%2F\` encoded, so it did not cover this form\. \#\#\# Impact An unauthenticated attacker can bypass route rules that protect paths served by
