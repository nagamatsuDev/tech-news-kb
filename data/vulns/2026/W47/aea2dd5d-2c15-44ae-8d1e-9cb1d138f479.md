# In the Linux kernel, the following vulnerability has been resolved\: smb\: client\: stop processing a read response after a receive error \.\.\.

- **ID**: CVE\-2026\-99295
- **危険度**: High（重要） (CVSS 7.5)
- **OS**: Linux
- **公開**: 2026-11-16

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
smb\: client\: stop processing a read response after a receive error
  
cifs\_read\_iter\_from\_socket\(\) may call cifs\_reconnect\(\) before returning an  
error\.  The reconnect path aborts pending mids and invokes their callbacks\.  
The callback can then release the cifs\_io\_subrequest containing rdata\.
  
cifs\_readv\_receive\(\) nevertheless continues after a negative return and may  
dereference rdata in cifs\_readv\_discard\(\)\.  KASAN reports the resulting  
UAF\:
  
  BUG\: KASAN\: slab\-use\-after\-free in cifs\_readv\_receive  
  Read of size 4 by task cifsd  
  cifs\_readv\_receive \(fs/smb/client/transport\.c\:1284\)  
  cifs\_demultiplex\_thread \(fs/smb/client/connect\.c\:1355\)  
  kthread \(kernel/kthread\.c\:436\)  
  ret\_from\_fork \(arch/x86/kernel/process\.c\:158\)
  
  Freed by task 148\:  
  netfs\_put\_subrequest \(fs/netfs/objects\.c\:267\)  
  netfs\_read\_collection \(fs/netfs/read\_collect\.c\:460\)  
  netfs\_wait\_for\_in\_progress \(fs/netfs/misc\.c\:462\)
  
Return the socket error immediately, as this path did before the iterator  
conversion\.  This also avoids adding a negative length to total\_read\.
