# In the Linux kernel, the following vulnerability has been resolved\: net\: restore refcount ordering for lockless socket access Before co\.\.\.

- **ID**: CVE\-2026\-99676
- **危険度**: Critical（緊急） (CVSS 9.8)
- **OS**: Linux
- **公開**: 2026-11-20

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
net\: restore refcount ordering for lockless socket access
  
Before commit fb041bb7c0a9 \("locking/refcount\: Consolidate implementations  
of refcount\_t"\), default builds implemented refcount\_inc\_not\_zero\(\) using  
atomic\_add\_unless\(\), which provided full memory ordering on success\. The  
commit removed that ordering on weakly ordered architectures, allowing  
accesses after a successful reference acquisition to be reordered before  
it\.
  
Use refcount\_inc\_not\_zero\_acquire\(\) in the IPv4 and IPv6 established  
lookups and in inet\_twsk\_purge\(\), where the socket is validated again  
after taking a reference\.
  
bpf\_sk\_assign\(\) can receive a socket pointer obtained through BTF  
without a reference\. Use acquire ordering when it takes its own reference  
for a refcounted socket\.
  
Use refcount\_set\_release\(\) when setting refcounts in the SYN cookie,  
TCP Fast Open, request migration, and TIME\_WAIT paths\. Keep the existing  
TIME\_WAIT smp\_wmb\(\), which separately orders the refcount store before  
ehash publication\.
