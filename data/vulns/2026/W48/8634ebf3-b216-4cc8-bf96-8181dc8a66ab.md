# When Request\:\:getBaseUrl\(\) does not find the script name at the start of the request URI, it looks for it further into the path\.

- **ID**: CVE\-2026\-135802
- **危険度**: High（重要） (CVSS 8.1)
- **言語**: PHP
- **公開**: 2026-11-24

## 原文

When Request\:\:getBaseUrl\(\) does not find the script name at the start of the request URI, it looks for it further into the path\. This supports web servers that rewrite every URL to a front controller in a subdirectory\. The base URL then kept everything before the script name, and the client chooses that part\. A request URI starting with // or /\\ made the base URL start with a host\.
  
With SCRIPT\_NAME\=/public/index\.php, a request for //evil\.example/public/index\.php/login is routed to /login, with the base URL //evil\.example/public/index\.php and the base path //evil\.example/public\. The URLs generated for that page then point to evil\.example\:  
\- links built with path\(\) and the actions of forms, so a login form sends the credentials of the user to evil\.example;  
\- redirects to generated URLs, such as the ones of redirectToRoute\(\);  
\- assets referenced with a relative path through asset\(\), so the page can load scripts from evil\.example\.
  
The attacker has to make a user follow a crafted link, such as https\://app\.example//evil\.example/public/index\.php/login\. framework\.trusted\_hosts does not help, since the host of the request is the real one\.
  
Applications are affected when their front controller is in a subdirectory and the web server sends it URIs that do not start with that directory\. A \.htaccess file at the root of the project that rewrites every URL to public/ does that, for instance\.
  
Applications are also affected when the web server sets SCRIPT\_NAME to the path of the request\. Some nginx configurations do that when they send every request to the front controller without fastcgi\_split\_path\_info\. php \-S does it too, with a router script outside the document root\. A request for /\\evil\.example/index\.php then gets the base URL /\\evil\.example/index\.php, which browsers read as a link to evil\.example\.
  
The configurations recommended in the Symfony documentation are not affected\.
  
Request\:\:getBaseUrl\(\) now returns an empty base URL when the request URI starts with // or /\\\.
