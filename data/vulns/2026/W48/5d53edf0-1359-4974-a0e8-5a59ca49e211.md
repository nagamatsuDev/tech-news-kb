# The WP Job Portal – AI\-Powered Recruitment System for Company or Job Board website plugin for WordPress is vulnerable to Authentication B\.\.\.

- **ID**: CVE\-2026\-135641
- **危険度**: Critical（緊急） (CVSS 9.1)
- **言語**: PHP
- **公開**: 2026-11-26

## 原文

The WP Job Portal – AI\-Powered Recruitment System for Company or Job Board website plugin for WordPress is vulnerable to Authentication Bypass leading to Account Takeover in all versions up to, and including, 2\.7\.2 This is due to a flaw in \`WPJOBPORTALuser\:\:\_\_construct\(\)\` where the non\-empty guard on the \`wpjobportal\-socialid\` cookie is evaluated against the raw cookie value before \`sanitize\_key\(\)\` is applied — allowing a value composed entirely of characters outside \`\[a\-z0\-9\_\-\]\` to pass the guard, be reduced to an empty string by \`sanitize\_key\(\)\`, and be used as the literal value in a \`WHERE socialid \= ''\` database query that matches the first portal account whose \`socialid\` column is empty\. This makes it possible for unauthenticated attackers to be bound to an existing WP Job Portal Employer or Jobseeker account, gaining the ability to create, edit, and delete the victim's companies, job listings, resumes, and applications, as well as overwrite the linked WordPress user's first name, last name, and display name via the \`saveuser\`→\`syncWPUserName\(\)\` path\. Exploitation is viable on virtually all installations because every portal account not registered through the social\-login flow retains the default empty \`socialid\` value; nonce checks on downstream actions such as \`savecompany\` and \`saveuser\` do not mitigate this issue because those nonces are minted within the already\-hijacked session and validate against the attacker's own subsequent requests\. Successful exploitation gives the attacker control of a distinct, already\-privileged WP Job Portal Employer / Jobseeker \(bound to a specific WordPress user\) account; it does not promote the attacker's original account\.
