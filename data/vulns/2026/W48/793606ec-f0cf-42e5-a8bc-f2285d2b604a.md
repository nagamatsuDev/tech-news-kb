# Improper Verification of Cryptographic Signature vulnerability in Erlang OTP ssl \(ssl\_handshake module\) allows an on\-path attacker to imp\.\.\.

- **ID**: CVE\-2026\-124286
- **危険度**: Critical（緊急） (CVSS 9.1)
- **公開**: 2026-11-24

## 原文

Improper Verification of Cryptographic Signature vulnerability in Erlang OTP ssl \(ssl\_handshake module\) allows an on\-path attacker to impersonate any server to a TLS 1\.2 or DTLS client\.
  
When a server sends no Certificate message and a ServerKeyExchange without a signature, ssl\_handshake\:decode\_server\_key/3 reports the signature algorithm as anon, and ssl\_handshake\:verify\_signature/5 returns true for anon without a public key\. The client does not require a certificate for a certificate\-authenticated key exchange, so the handshake completes for the ecdhe\_rsa, ecdhe\_ecdsa, dhe\_rsa and dhe\_dss key exchanges with a cipher suite the client offered\. Certificate path validation, verify\_fun and the hostname check do not run, and ssl\:connect/3 returns \{ok, Socket\} with \{verify, verify\_peer\} set\. The TLS 1\.3 client is not affected\.
  
This issue affects OTP from OTP 17\.0 before OTP 27\.3\.4\.14, OTP 28\.5\.0\.9, and OTP 29\.0\.3, corresponding to ssl from 5\.3\.4 before 11\.2\.12\.10, 11\.6\.0\.8, and 11\.7\.3\.
