# To escape a bound parameter, or a name passed to a catalog function, psqlODBC has to know where each multibyte character of the client en\.\.\.

- **ID**: CVE\-2026\-136500
- **危険度**: High（重要） (CVSS 8.1)
- **公開**: 2026-11-25

## 原文

To escape a bound parameter, or a name passed to a catalog function, psqlODBC has to know where each multibyte character of the client encoding ends\. It treated a client encoding named by an alias the server accepts, such as WIN950, Windows950 or big\-5 for BIG5, as single\-byte, and it accepted too narrow a range of lead bytes for JOHAB, EUC\_TW, EUC\_CN and EUC\_KR\. A quote byte that the server reads as part of such a character was then not doubled, or a quote the server reads on its own was taken for part of a character, and the literal ended early\.
  
An end user who controls one bound character parameter, or a name the application passes to a catalog function such as SQLTables\(\), can run SQL with the rights of the application's database role\. This requires a connection that is not in UTF\-8\: the ANSI driver, or the ANSI entry points, with one of these client encodings\. For bound parameters the driver must also be substituting parameters itself, as it does with UseServerSidePrepare\=0 or a cursor type other than forward\-only\.
  
Versions up to and including psqlODBC 18\.00\.0006 are affected\.
