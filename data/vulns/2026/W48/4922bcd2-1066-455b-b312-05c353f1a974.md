# Summary MCUboot enforces several security\-critical invariants on the boot, image\-swap, and validation paths using assert\(\)\.

- **ID**: CVE\-2026\-16665
- **危険度**: High（重要） (CVSS 7.4)
- **公開**: 2026-11-24

## 原文

Summary
  
MCUboot enforces several security\-critical invariants on the boot, image\-swap, and validation paths using assert\(\)\. In a standard release/production build \(NDEBUG defined\) assert\(\) expands to a no\-op, so an invariant the code intends to halt on instead falls through, and execution continues with the bad or inconsistent state\. Where the guarded condition is attacker\-influenceable through the flash\-write boundary \(serial\-recovery / DFU\), this is a security check that is simply absent in release builds\.
  
This is one root cause \(assert\-as\-security\-guard, no\-op under NDEBUG\) with one fix approach \(replace the security\-critical asserts with real fail\-closed checks\), so it is filed as a single advisory covering the enumerated sites\.
  
Worst reachable instance — inconsistent swap status completes the swap without validation
  
In the swap\-resume status read, an inconsistent status \(erased\_sections &gt; 1\) is detected, logged, and — when MCUBOOT\_VALIDATE\_PRIMARY\_SLOT is disabled — is meant to abort, because "there is no way to be sure the swapped primary slot is OK\." The abort is assert\(0\)\:
  
boot/bootutil/src/swap\_move\.c\:181\-194 — if \(erased\_sections &gt; 1\) \{ \.\.\. \#if \!defined\(MCUBOOT\_VALIDATE\_PRIMARY\_SLOT\) / \.\.\. abort\! / assert\(0\); \#endif \}, then execution falls through to compute bs\-&gt;op/idx/state from the inconsistent status \(lines 197\-208\) and return 0 \(success\)\.  
boot/bootutil/src/swap\_offset\.c\:266\-280 — identical pattern; falls through to bs\-&gt;op/idx/state and return 0\.  
boot/bootutil/src/swap\_scratch\.c\:227\-241 — same invalid/assert\(0\) pattern for the scratch backend\.
  
Under NDEBUG with primary\-slot validation off, the inconsistent status is neither aborted \(assert is a no\-op\) nor re\-validated \(validation off\), so boot\_complete\_partial\_swap\(\) finishes the swap on inconsistent metadata and the primary slot is booted without a signature check\. An attacker who can write the swap\-status trailer can craft the inconsistent status\.
  
Reachability \(threat model\)\. Secondary slot \+ scratch trailers are A2\-writable by definition \(that is what a DFU upload is\)\. Under MCUBOOT\_SERIAL\_RECOVERY the primary trailer is A2\-writable too\: boot/boot\_serial/src/boot\_serial\.c\:978 opens flash\_area\_id\_from\_multi\_image\_slot\(img\_num, 0\) \(\=\= primary\) and writes from offset 0 bounded by area\_size, so it can paint the primary swap\-status/magic\. This is how the A2 \(recovery/DFU, unauthenticated by design\) attacker influences the guarded condition\. Property violated\: P1 \(image authenticity / secure\-boot bypass\) when un\-revalidated content is booted, and P6 \(boot/recovery availability\)\.
  
Second reachable instance — resume\-path swap\_size from an unguarded trailer
  
boot/bootutil/src/loader\.c\:1190\-1193\: the swap resume branch does fap \= boot\_find\_status\(\.\.\.\); assert\(fap \!\= NULL\); rc \= boot\_read\_swap\_size\(fap, &amp;bs\-&gt;swap\_size\); assert\(rc \=\= 0\);\. boot\_find\_status\(\) \(boot/bootutil/src/bootutil\_misc\.c\:166\-204\) searches \{scratch, primary\} and, on no\-valid\-magic\-match, returns the last\-iterated area \(primary\), not NULL — so assert\(fap \!\= NULL\) cannot fire even in debug, and under NDEBUG neither assert fires\. swap\_size is then read from an A2\-writable \(serial\-recovery primary, or scratch\) trailer with no fail\-closed handling\. This is the same swap\-metadata\-trust family as the recorded resume/swap\_size disclosure\.
  
Reachable\-security sites \(center the fix here\)
  
1\. boot/bootutil/src/swap\_move\.c\:193 — inconsistent\-status assert\(0\), falls through to complete swap\. A2 \+ \!VALIDATE\_PRIMARY\. \[worst\]  
2\. boot/bootutil/src/swap\_offset\.c\:278 — same, swap\-offset backend\.  
3\. boot/bootutil/src/swap\_scratch\.c\:239 — same, swap\-scratch backend\.  
4\. boot/bootutil/src/loader\.c\:1191 and \:1193 — resume assert\(fap \!\= NULL\) / assert\(rc \=\= 0\) guarding swap\_size read from an A2\-writable trailer; compounded by boot\_find\_status\(\) never returning NULL\.
  
\(Truncated\. The full description is in the advisory\: https\://github\.com/mcu\-tools/mcuboot/security/advisories/GHSA\-cr9j\-p626\-pwcc\)
