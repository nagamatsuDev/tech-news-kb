# The W3 Total Cache plugin for WordPress is vulnerable to unauthorized File Deletion in all versions up to, and including, 2\.11\.0 via the \.\.\.

- **ID**: CVE\-2026\-119071
- **危険度**: High（重要） (CVSS 8.1)
- **言語**: PHP
- **公開**: 2026-11-27

## 原文

The W3 Total Cache plugin for WordPress is vulnerable to unauthorized File Deletion in all versions up to, and including, 2\.11\.0 via the \`ajax\_revert\(\)\` AJAX handler\. The vulnerability exists because the \`remove\_optimizations\(\)\` function reads attacker\-controlled values from the unprotected \`w3tc\_imageservice\` post meta key — which carries no underscore prefix and no registered authorization callback, making it writable by any user with \`edit\_post\` capability via WordPress's built\-in custom\-fields AJAX endpoint — and passes those values directly to \`wp\_delete\_attachment\(\)\` with no check that the referenced ID is a child of the caller's own post, is an actual attachment, or that the caller holds \`delete\_post\` capability on it\. This makes it possible for authenticated attackers with Author\-level access or above to permanently delete any WordPress attachment in the media library, including media files owned by other users along with their associated files on disk, regardless of ownership — a capability not available through the normal WordPress interface\. The revert nonce is exposed via \`wp\_localize\_script\` on \`/wp\-admin/upload\.php\` to any user with \`upload\_files\` capability, ensuring the nonce check that is present does not serve as a meaningful barrier to Author\-level exploitation\.
