# To build positioned updates and to describe columns, psqlODBC matches the names in a statement against the catalog\.

- **ID**: CVE\-2026\-136501
- **危険度**: High（重要） (CVSS 7.1)
- **OS**: Windows
- **公開**: 2026-11-25

## 原文

To build positioned updates and to describe columns, psqlODBC matches the names in a statement against the catalog\. Where it matched differently from the server, it used another table or column\:
  
\- Table and schema names were compared case\-insensitively in its column\-information cache, so users could be taken for another user's "Users", and the driver then evaluated that table's column default to answer @@IDENTITY\.  
\- In FROM ONLY t, ONLY was taken for the table name\.  
\- Column names were compared case\-insensitively, so with Parse\=1 the type of another column could decide the size of the application's buffer, which a fetch then overflowed\.  
\- In a database whose encoding is single\-byte, such as LATIN1 or SQL\_ASCII, the server folds the accented letters of an unquoted name by its own locale, while the driver folded only A\-Z, so ÉTAT could be taken for another user's "État" instead of état\.  
\- On systems other than Windows, in a Turkish or Azeri locale, an unquoted I was not folded to i, and keywords and ODBC function names did not match\.  
\- Without a schema name, SQLSpecialColumns\(\) could report the key columns of another user's same\-named temporary table, and SQLPrimaryKeys\(\) could take another user's index named &lt;table&gt;\_pkey for the primary key of a table without one\.  
\- After search\_path changed other than through a plain SET statement, positioned writes went to the same\-named table in the previously current schema\.  
\- SQLBulkOperations\(\) trusted the ctid stored inside a variable\-length bookmark handed back by the application, and ignored the WHERE clause that restricted the cursor, so a forged bookmark read, updated or deleted any row of the cursor's table\.
  
A database user who can create a table in a schema on another user's search\_path can redirect that user's positioned updates, inserts and deletes to a table of their choosing, where they run with the victim's rights, or run an expression of their choosing under the victim's role\.
  
Versions up to and including psqlODBC 18\.00\.0006 are affected\.
