# Allocation of Resources Without Limits or Throttling vulnerability in Erlang OTP inets \(httpd\_script\_env module\) allows an unauthenticate\.\.\.

- **ID**: CVE\-2026\-116382
- **危険度**: High（重要） (CVSS 8.2)
- **公開**: 2026-11-24

## 原文

Allocation of Resources Without Limits or Throttling vulnerability in Erlang OTP inets \(httpd\_script\_env module\) allows an unauthenticated remote attacker to exhaust the atom table of an httpd server that serves ESI scripts\.
  
When mod\_esi builds the environment for an ESI callback, httpd\_script\_env\:http\_env\_element/3 checks that a request header name already exists as an atom, then creates the atom http\_&lt;header\-name&gt; with list\_to\_atom/1\. Atoms are never garbage collected, and each new atom passes the existence check on a later request\. So a header named node creates http\_node, a header named http\_node creates http\_http\_node, and so on\. A stream of requests to any ESI URL grows the atom table until it reaches its limit \(\+t\), and then the whole Erlang VM aborts, together with every application on the node\.
  
This issue affects OTP from OTP 17\.0 before OTP 27\.3\.4\.20, OTP 28\.5\.0\.9, and OTP 29\.1\.3, corresponding to inets from 5\.10 before 9\.3\.2\.9, 9\.6\.2\.5, and 9\.8\.2\. Whether OTP before OTP 17\.0, corresponding to inets before 5\.10, is affected is unknown\.
