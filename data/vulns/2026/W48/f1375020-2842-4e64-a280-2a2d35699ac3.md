# In Valkey before 7\.2\.15, 8\.0\.x before 8\.0\.12, 8\.1\.x before 8\.1\.11, 9\.0\.x before 9\.0\.7, 9\.1\.x before 9\.1\.3 and 9\.2\.0\-rc1, running in clust\.\.\.

- **ID**: CVE\-2026\-136156
- **危険度**: High（重要） (CVSS 8.8)
- **公開**: 2026-11-24

## 原文

In Valkey before 7\.2\.15, 8\.0\.x before 8\.0\.12, 8\.1\.x before 8\.1\.11, 9\.0\.x before 9\.0\.7, 9\.1\.x before 9\.1\.3 and 9\.2\.0\-rc1, running in cluster mode, clusterCreatePublishMsgBlock computes the length of the cluster bus message for a PUBLISH or SPUBLISH as a size\_t but passes it to createClusterMsgSendBlock as a uint32\_t\. When the channel and message together exceed 4 GiB, the length is truncated, a buffer far smaller than the message is allocated, and the full channel and message are then copied into it\. An authenticated user who can publish, for example by building the arguments in a script, can overflow the heap with attacker\-controlled bytes\. This reliably crashes the server and may lead to remote code execution\. Servers that do not run in cluster mode are not affected\.
