# jline3 leads to ReDoS in Built\-in Less Viewer Search

- **ID**: CVE\-2026\-77423 / GHSA\-2v9w\-34q6\-wpqx
- **危険度**: High（重要） (CVSS 7.5)
- **言語**: Java/Kotlin
- **パッケージ**: Maven/org\.jline\:jline\-builtins &lt; 3\.30\.15 → 3\.30\.15, Maven/org\.jline\:jline\-builtins &gt;\= 4\.0\.0, &lt; 4\.3\.1 → 4\.3\.1
- **公開**: 2026-11-23

## 原文

\#\#\# Summary The JLine3 built\-in \`less\` pager compiles user\-supplied search patterns directly as Java regular expressions with no sanitization, timeout, or backtracking bound\. A malicious pattern such as \`\(a\+\)\+b\` can trigger catastrophic backtracking and hang the session thread at 100% CPU\. In deployments that expose \`less\` over Telnet or SSH, this becomes a denial\-of\-service issue for the affected session and can be used to exhaust a bounded session pool\. \#\#\# Details \`Less\.getPattern\(\)\` in \`builtins/src/main/java/org/jline/builtins/Less\.java\` compiles the user\-controlled search string directly
