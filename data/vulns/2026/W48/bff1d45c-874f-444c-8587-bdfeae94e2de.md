# In the Linux kernel, the following vulnerability has been resolved\: tracing/histograms\: Verify event\_call identity when updating synth\_e\.\.\.

- **ID**: CVE\-2026\-99233
- **危険度**: High（重要） (CVSS 7.8)
- **OS**: Linux
- **公開**: 2026-11-02

## 原文

In the Linux kernel, the following vulnerability has been resolved\:
  
tracing/histograms\: Verify event\_call identity when updating synth\_event refcount
  
In event\_hist\_trigger\_parse\(\) and hist\_unreg\_all\(\), the histogram  
registration and unregistration paths look up find\_synth\_event\(\) using  
trace\_event\_name\(file\-&gt;event\_call\) and adjust se\-&gt;ref if a match is  
found\.
  
Because find\_synth\_event\(\) only compares the event basename, registering  
or removing a histogram on a non\-synthetic trace event whose basename  
matches a synthetic event erroneously modifies the synthetic event's  
reference count\.  If a histogram is registered on the non\-synthetic  
event before the synthetic event is created and removed afterwards,  
se\-&gt;ref is decremented without a matching increment, allowing the  
synthetic event to be freed while an active histogram action still holds  
a pointer to it\.
  
Introduce find\_synth\_event\_call\(\) to verify that &amp;se\-&gt;call matches  
file\-&gt;event\_call before adjusting se\-&gt;ref\.
