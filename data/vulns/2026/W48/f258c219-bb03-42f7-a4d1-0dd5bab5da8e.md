# In Valkey 8\.0\.x before 8\.0\.11, 8\.1\.x before 8\.1\.10, 9\.0\.x before 9\.0\.6 and 9\.1\.x before 9\.1\.2, the RDMA transport's pending\-data handler \.\.\.

- **ID**: CVE\-2026\-136157
- **危険度**: High（重要） (CVSS 7.5)
- **公開**: 2026-11-24

## 原文

In Valkey 8\.0\.x before 8\.0\.11, 8\.1\.x before 8\.1\.10, 9\.0\.x before 9\.0\.6 and 9\.1\.x before 9\.1\.2, the RDMA transport's pending\-data handler walks its connection list with an iterator that caches the next entry\. A command processed from inside that loop, such as CLIENT KILL, can synchronously free another client's connection, and closing an RDMA connection did not remove it from the pending list, so the handler then uses freed memory\. An authenticated user can use this to reliably crash the server, and the freed heap chunk can be reclaimed with attacker\-influenced bytes\. Only servers built with RDMA support \(USE\_RDMA\) and configured with an RDMA listener are affected\.
