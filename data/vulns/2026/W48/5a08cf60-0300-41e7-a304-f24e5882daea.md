# Out\-of\-bounds Write vulnerability in the external term format decoder in Erlang OTP erts allows an attacker who controls the input to bin\.\.\.

- **ID**: CVE\-2026\-116293
- **危険度**: High（重要） (CVSS 7.0)
- **公開**: 2026-11-24

## 原文

Out\-of\-bounds Write vulnerability in the external term format decoder in Erlang OTP erts allows an attacker who controls the input to binary\_to\_term/1,2 to abort the Erlang VM via a NEWER\_REFERENCE\_EXT term with a zero\-length ID\. decoded\_size in erts/emulator/beam/external\.c accepts a reference whose 16\-bit Len field is zero, but dec\_term always reads one ID word\. dec\_term then runs 4 bytes ahead of the position that decoded\_size validated\. It decodes the bytes that follow as terms that were never sized, and writes past the reserved process heap\.
  
The abort takes down every process on the node\. Supervision, try/catch and the safe option do not prevent it\. enif\_binary\_to\_term\(\) and the distribution protocol reach the same decoder, and distribution is assumed to run on trusted networks only\. NEW\_REFERENCE\_EXT also accepts a zero length, but its range check on the first ID word rejects the shifted input\. On 32\-bit builds, a zero\-length reference of either type at the end of the input, followed by trailing bytes, can write one word past the reserved heap\.
  
This issue affects OTP from OTP 17\.0 before OTP 27\.3\.4\.20, OTP 28\.5\.0\.9, and OTP 29\.1\.3, corresponding to erts from 6\.0 before 15\.2\.7\.15, 16\.4\.0\.8, and 17\.1\.2\. Whether OTP before OTP 17\.0, corresponding to erts before 6\.0, is affected is unknown\.
