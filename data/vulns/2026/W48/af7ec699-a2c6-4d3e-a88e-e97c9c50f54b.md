# Use of Externally\-Controlled Input to Select Classes or Code \('Unsafe Reflection'\) vulnerability in elixir\-ecto db\_connection allows an a\.\.\.

- **ID**: CVE\-2026\-133555
- **危険度**: High（重要） (CVSS 8.9)
- **公開**: 2026-11-24

## 原文

Use of Externally\-Controlled Input to Select Classes or Code \('Unsafe Reflection'\) vulnerability in elixir\-ecto db\_connection allows an attacker to execute arbitrary code via a forged DBConnection\.Stream or DBConnection\.PrepareStream struct\. The Enumerable implementations of both structs in lib/db\_connection\.ex run with the options stored in the struct\. The \:log option accepts a \{module, function, arguments\} tuple, which DBConnection applies\. When code enumerates a forged struct, DBConnection calls the chosen function\.
  
This issue is not exploitable in db\_connection alone\. It is, in theory, a vulnerability of the downstream component\. The root cause is a component that decodes untrusted input with \:erlang\.binary\_to\_term/2 and does not restrict which terms the result contains\. The \:safe option does not reject structs, and these structs contain only plain terms\. Structs of other libraries can possibly lead to the same result, so a component that decodes untrusted terms stays at risk independently of db\_connection\. This record exists because the struct was used in attacks on such components\.
  
This issue affects db\_connection\: from 1\.1\.0 before 2\.10\.3\.
