# FreeRDP before 3\.32\.2 has a heap out\-of\-bounds write in the RDPGFX client because the delete\_surface callback truncates surface hash keys\.\.\.

- **ID**: CVE\-2026\-121958
- **危険度**: High（重要） (CVSS 7.5)
- **公開**: 2026-11-04

## 原文

FreeRDP before 3\.32\.2 has a heap out\-of\-bounds write in the RDPGFX client because the delete\_surface callback truncates surface hash keys to 16 bits, leaving the surface table inconsistent so HashTable\_GetKeys writes past its allocated key array\. A malicious or man\-in\-the\-middle RDP server can exploit this by creating surfaceId 0xFFFF, closing the RDPGFX channel, sending repeated DELETESURFACE PDUs, and then sending ENDFRAME or RESETGRAPHICS\.
