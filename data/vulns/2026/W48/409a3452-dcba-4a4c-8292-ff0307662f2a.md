# Relative path traversal in ex\_aws allows an attacker who controls an S3 object key to escape the intended bucket or key prefix\.

- **ID**: CVE\-2026\-59698
- **危険度**: High（重要） (CVSS 7.4)
- **公開**: 2026-11-24

## 原文

Relative path traversal in ex\_aws allows an attacker who controls an S3 object key to escape the intended bucket or key prefix\.
  
When ex\_aws builds a path\-style S3 request, ExAws\.Operation\.S3\.add\_bucket\_to\_path/2 in lib/ex\_aws/operation/s3\.ex joins the bucket name and the object key into a single path string and then normalizes it, collapsing \. and \.\. segments the way a filesystem path would\. Because the bucket is the first segment of the combined string, a leading \.\./ in the object key pops the bucket off the path\. With bucket mybucket and a key of \.\./victim/secret\.txt, the combined /mybucket/\.\./victim/secret\.txt normalizes to /victim/secret\.txt, so the request \(signed with the application's own credentials\) is sent to bucket victim\. The same mechanism collapses \.\./ within a key, defeating any isolation an application enforces by prepending a trusted prefix\.
  
Only the default path\-style configuration is affected; requests built with virtual\_host\: true do not run this normalization\. Because S3 treats object keys as opaque and does not resolve \.\. itself, the client\-side normalization introduces a traversal that would not otherwise exist\. Any application that derives an S3 object key from untrusted input and relies on the bucket, or a key prefix, as a tenant or trust boundary is exposed to cross\-bucket or cross\-prefix read and write, depending on the operation and the credentials' permissions\.
  
This issue affects ex\_aws\: from 2\.1\.7 before 2\.8\.0\.
