# Improper Validation of Specified Quantity in Input vulnerability in the BER decoder in Erlang/OTP snmp allows an unauthenticated remote a\.\.\.

- **ID**: CVE\-2026\-116225
- **危険度**: High（重要） (CVSS 8.7)
- **公開**: 2026-11-24

## 原文

Improper Validation of Specified Quantity in Input vulnerability in the BER decoder in Erlang/OTP snmp allows an unauthenticated remote attacker to exhaust CPU via an SNMP message that contains an OBJECT IDENTIFIER with a very long sub\-identifier\.
  
snmp\_pdus\:dec\_oid\_element/3 does not limit the number of base\-128 octets in a sub\-identifier, and snmp\_pdus\:dec\_oid\_elements/3 does not limit the number of sub\-identifiers, so one sub\-identifier can span the whole datagram\. When the value exceeds the native integer size, each further octet copies a growing bignum, and decoding time grows quadratically with the sub\-identifier length\. The agent and the manager decode OIDs before they check community strings or SNMPv3 credentials, inside the single network interface process \(snmpa\_net\_if or snmpm\_net\_if\)\. That process does not read the next datagram until decoding completes\.
  
This issue affects OTP from OTP 17\.0 before OTP 27\.3\.4\.20, OTP 28\.5\.0\.9, and OTP 29\.1\.3, corresponding to snmp from 4\.25\.1 before 5\.18\.2\.3, 5\.20\.2\.4, and 5\.20\.7\. Whether OTP before OTP 17\.0, corresponding to snmp before 4\.25\.1, is affected is unknown\.
