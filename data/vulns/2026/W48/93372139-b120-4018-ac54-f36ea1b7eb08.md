# The Groundhogg plugin for WordPress is vulnerable to Cross\-Site Request Forgery in versions up to, and including, 4\.11 This is due to the\.\.\.

- **ID**: CVE\-2026\-130805
- **危険度**: High（重要） (CVSS 8.1)
- **言語**: PHP
- **公開**: 2026-11-26

## 原文

The Groundhogg plugin for WordPress is vulnerable to Cross\-Site Request Forgery in versions up to, and including, 4\.11 This is due to the Admin\_Page\:\:page\(\) callback dispatching methods named directly by the \$\_REQUEST\['action'\] parameter via call\_user\_func\(\[\$this, \$action\]\) without verifying a nonce\: the only nonce check lives in process\_action\(\) \(admin\_init\), which prefixes the action with 'process\_' before dispatching, so an attacker who supplies action\=process\_delete causes process\_action\(\) to look up the nonexistent 'process\_process\_delete' method and bail without ever calling wp\_verify\_nonce\(\), while page\(\) subsequently invokes the real process\_delete\(\) \(and other process\_\* methods such as process\_spam, process\_status\_change, process\_edit\) with no CSRF token of its own\. This makes it possible for unauthenticated attackers to delete arbitrary contacts, change contact opt\-in status \(including marking contacts as spam, which also appends their IP to the site\-wide disallowed\_keys option\), and perform other state\-changing actions via a forged request granted they can trick a site administrator \(or any user holding the relevant Groundhogg capability such as delete\_contacts/edit\_contacts\) into performing an action such as clicking on a link\.
