# The WP STAGING – Backups &amp; Restore, Migration &amp; Clone Plugin – Cloud Backups, Scheduled Backups plugin for WordPress is vulnerable to Aut\.\.\.

- **ID**: CVE\-2026\-109586
- **危険度**: High（重要） (CVSS 7.5)
- **言語**: PHP
- **公開**: 2026-11-26

## 原文

The WP STAGING – Backups &amp; Restore, Migration &amp; Clone Plugin – Cloud Backups, Scheduled Backups plugin for WordPress is vulnerable to Authorization Bypass in all versions up to, and including, 4\.17\.0 via the \`REQUEST\_URI\` query parameter\. This is due to a parser\-differential flaw in \`showLoginForm\(\)\`\: the plugin's \`isRestUrl\(\)\` function performs an unanchored \`strpos\(\)\` prefix match against the full \`REQUEST\_URI\` — including the query string — and short\-circuits all authorization checks \(including \`isStagingSite\(\)\` and \`current\_user\_can\('manage\_options'\)\`\) whenever it detects a REST\-like URL, while WordPress core only treats a request as a REST API call when the \`rest\_route\` query variable is non\-empty\. This makes it possible for unauthenticated attackers to bypass the staging\-site login gate entirely by appending an empty \`rest\_route\` parameter \(e\.g\. \`/wp\-json/?rest\_route\=\`\), causing the plugin to skip its gate while core proceeds to render the ordinary theme front end, exposing the full theme\-rendered contents of the staging site — including private post content, page\-builder output, WooCommerce pages, and site search results over the staging database\. This bypass only affects staging sites where the login gate is active, which is the default state for any site cloned by the plugin when the \`wpstg\_is\_staging\_site\` option is set to \`true\` or the \`\.wp\-staging\` marker file is present in \`ABSPATH\`\.
