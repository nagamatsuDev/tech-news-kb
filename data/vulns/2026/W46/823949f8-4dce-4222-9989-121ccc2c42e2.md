# Zephyr HTTPサーバーのHTTP/2フロントエンドは、スクラッチ出力として接続を受信します。

- **ID**: CVE\-2026\-82391
- **危険度**: Critical（緊急） (CVSS 9.1)
- **公開**: 2026-11-10

## 原文

The HTTP/2 front\-end of the Zephyr HTTP server aliased connection receive state as a scratch output\. In subsys/net/lib/http/http\_server\_http2\.c, handle\_http2\_static\_fs\_resource\(\) passed &amp;client\-&gt;data\_len as the file\_size out\-parameter of http\_server\_find\_file\(\)\. client\-&gt;data\_len is the count of unprocessed bytes remaining in the fixed\-size per\-connection receive buffer client\-&gt;buffer\[CONFIG\_HTTP\_SERVER\_CLIENT\_BUFFER\_SIZE\] \(256 bytes by default\), an invariant every frame handler and the socket receive path rely on\. Serving any static file therefore replaced that bounded value with the file's on\-disk size, and nothing resets it afterwards\.
  
The defect is reached by an unauthenticated HTTP/2 GET for any file under the web root, in applications that register a static\-filesystem resource \(HTTP\_RESOURCE\_TYPE\_STATIC\_FS\) with CONFIG\_FILE\_SYSTEM\=y; CONFIG\_HTTP\_SERVER\_VERSION\_2 is enabled by default and no TLS or credentials are required on this path\. Once client\-&gt;data\_len exceeds the buffer size, the frame dispatch loop in subsys/net/lib/http/http\_server\_core\.c keeps parsing past the end of the received data, and the peer controls the bytes at client\-&gt;cursor, so it can choose which fabricated frame the state machine consumes next by appending bytes after its request\.
  
The inflated length defeats the only guards on the buffer\. parse\_http\_frame\_header\(\) and the per\-frame handlers read and skip up to a 24\-bit frame length beyond the buffer \(out\-of\-bounds read\); the compaction memmove\(client\-&gt;buffer, client\-&gt;cursor, client\-&gt;data\_len\) at the end of request handling copies the file\-size number of bytes into the 256\-byte buffer, overflowing the rest of struct http\_client\_ctx — including the current\_detail/current\_stream pointers, the parser\_settings function\-pointer table and the inactivity\_timer work handler — and the adjacent client contexts in static memory; and the subsequent zsock\_recv\(client\-&gt;fd, client\-&gt;buffer \+ client\-&gt;data\_len, sizeof\(client\-&gt;buffer\) \- client\-&gt;data\_len, 0\) underflows its size argument, writing attacker\-supplied data of attacker\-chosen length out of bounds\.
  
The impact is remote memory corruption in the server's single address space\: at minimum a crash or hang of the device, and plausibly control\-data overwrite leading to code execution\. The HTTP/1 and HTTP/3 static\-filesystem handlers already used a local variable and are unaffected; the fix makes the HTTP/2 handler use a local size\_t file\_size as well\.
