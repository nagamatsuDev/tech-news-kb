# Building a malicious package containing "//go\:cgo\_\*" compiler directives could inject arbitrary flags into the external linker invocation\.\.\.

- **ID**: CVE\-2026\-97041
- **危険度**: High（重要） (CVSS 8.8)
- **公開**: 2026-11-11

## 原文

Building a malicious package containing "//go\:cgo\_\*" compiler directives could inject arbitrary flags into the external linker invocation on ELF platforms\. The compiler and linker did not reject commas in "//go\:cgo\_import\_dynamic", "//go\:cgo\_export\_dynamic", "//go\:cgo\_export\_static", "//go\:cgo\_import\_static", and "//go\:cgo\_dynamic\_linker" directives, and the linker passed the dynamic linker path using "\-Wl,\-\-dynamic\-linker,&lt;path&gt;"\. Furthermore, the two\-argument form of "//go\:cgo\_import\_dynamic" \(which is permitted in non\-cgo Go source files\) could overwrite the external symbol name of a symbol already marked for cgo export\. A symbol name or dynamic linker path containing a comma or leading "@" could split "\-Wl,\-\-export\-dynamic\-symbol\=" or "\-Wl,\-\-dynamic\-linker," into arbitrary host linker flags or response file arguments\. The compiler and linker now reject commas in "//go\:cgo\_\*" symbol and dynamic linker directives, the linker passes "\-Wl,\-\-dynamic\-linker\=&lt;path&gt;", and "cgo\_import\_dynamic" no longer overwrites symbols exported via "cgo\_export\_dynamic" or "cgo\_export\_static"\.
