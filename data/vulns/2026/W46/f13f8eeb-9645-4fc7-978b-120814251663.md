# The user\-mode syscall verifiers for the charger driver API in drivers/charger/charger\_handlers\.c did not inspect the prop argument before\.\.\.

- **ID**: CVE\-2026\-91007
- **危険度**: High（重要） (CVSS 7.8)
- **公開**: 2026-11-12

## 原文

The user\-mode syscall verifiers for the charger driver API in drivers/charger/charger\_handlers\.c did not inspect the prop argument before copying union charger\_propval across the user/kernel boundary\. Two members of that union are function pointers — status\_notification \(CHARGER\_PROP\_STATUS\_NOTIFICATION\) and online\_notification \(CHARGER\_PROP\_ONLINE\_NOTIFICATION\), declared in include/zephyr/drivers/charger\.h — and z\_vrfy\_charger\_set\_prop\(\) forwarded the caller\-supplied union verbatim to the driver's set\_property callback for any property\. z\_vrfy\_charger\_get\_prop\(\) had the mirror defect and copied the stored kernel callback address back out to user memory\.
  
With CONFIG\_USERSPACE enabled, any user\-mode thread that has been granted a charger device object could call charger\_set\_prop\(\) with CHARGER\_PROP\_STATUS\_NOTIFICATION or CHARGER\_PROP\_ONLINE\_NOTIFICATION and an arbitrary pointer value\. Drivers that implement these properties — drivers/charger/charger\_max20335\.c, drivers/charger/charger\_pf1550\.c and drivers/charger/charger\_bq2518x\.c — store the pointer in device data and later invoke it from their interrupt work handlers, which run in supervisor mode, on any charger state change such as a cable plug/unplug\.
  
The result is a control\-flow hijack at kernel privilege from an unprivileged thread, defeating the isolation that CONFIG\_USERSPACE is meant to provide; the read path additionally disclosed a kernel code address to user mode, and clearing a notifier installed by a supervisor thread let user mode suppress charger notifications\. Supervisor\-mode callers of charger\_set\_prop\(\)/charger\_get\_prop\(\) are unaffected\.
  
The fix makes both verifiers reject the two notifier properties outright — including when the supplied callback is NULL, since the notifiers are device state — and adds a BUILD\_ASSERT on CHARGER\_PROP\_COMMON\_COUNT so that new properties force a re\-review of the union's user\-mode safety\.
