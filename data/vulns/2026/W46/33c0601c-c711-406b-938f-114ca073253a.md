# Authorization Bypass Through User\-Controlled Key vulnerability in elixir\-grpc grpc\_server and grpc allows an attacker to make a handler a\.\.\.

- **ID**: CVE\-2026\-124278
- **危険度**: High（重要） (CVSS 7.6)
- **公開**: 2026-11-13

## 原文

Authorization Bypass Through User\-Controlled Key vulnerability in elixir\-grpc grpc\_server and grpc allows an attacker to make a handler act on a resource other than the one named in the URL of an HTTP\-transcoded route, via a request with a gRPC Content\-Type\.
  
Only the transcoding clause of GRPC\.Server\.do\_handle\_request/4 \(grpc\_server/lib/grpc/server\.ex, and lib/grpc/server\.ex before the package split\) applies the route's path bindings to the request message\. The Cowboy handler picks that clause from the request Content\-Type, not from the route\. A request to a transcoded URL with application/grpc or application/grpc\-web is decoded from the body alone, so every path\-bound field takes its value from the body\. A gateway, proxy rule or WAF that authorizes on the URL path sees one resource while the handler receives another\.
  
This issue affects grpc\: from 0\.8\.0 before 1\.0\.0; grpc\_server\: from 1\.0\.0 before 1\.1\.0\.
