# Action Pack is a framework for handling and responding to web requests\.

- **ID**: CVE\-2026\-126083
- **危険度**: High（重要） (CVSS 7.4)
- **言語**: Ruby
- **公開**: 2026-11-10

## 原文

Action Pack is a framework for handling and responding to web requests\. From 8\.1 until 8\.1\.4\.1, Since Rails 8\.1\.0, ActionDispatch\:\:RemoteIp derives request\.remote\_ip from Rack\:\:Request\#forwarded\_for, which under Rack 3 reads the RFC 7239 Forwarded header in preference to X\-Forwarded\-For\. When a reverse proxy appends the client address to X\-Forwarded\-For but passes a client\-supplied Forwarded header through unchanged, request\.remote\_ip returns an address chosen by the client, and the IP spoofing check does not raise, because it compares only Client\-Ip with the forwarded addresses\. An unauthenticated attacker could therefore spoof request\.remote\_ip, possibly bypassing IP\-based access controls and rate limits keyed on the client address \(including the default by\: of rate\_limit\), and falsifying the client address in logs\. An application is affected if it meets all of these requirements\: Runs Rails 8\.1\.0 through 8\.1\.4 with Rack 3\. Under Rack 2\.2, forwarded\_for reads only X\-Forwarded\-For\. Is served behind a proxy that does not remove or overwrite a client\-supplied Forwarded header\. Relies on request\.remote\_ip for access control, rate limiting, or auditing\. The fix detects a spoofed Forwarded header only when the proxy also sets X\-Forwarded\-For\. An application whose proxy passes a client\-supplied Forwarded header through and sets no X\-Forwarded\-For remains exposed after upgrading, and should configure the proxy to remove or overwrite Forwarded, or apply the workaround below\. This issue is fixed in version 8\.1\.4\.1\.
