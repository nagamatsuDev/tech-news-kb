# OpenMage Magento LTS before 20\.18\.2 and 21\.0\.0\-beta1 before 21\.0\.0\-beta3には、管理者にクロスサイト要求の偽造脆弱性が含まれている。

- **ID**: CVE\-2026\-128049
- **危険度**: Critical（緊急） (CVSS 9.0)
- **公開**: 2026-11-13

## 概要（機械翻訳）

OpenMage Magento LTS before 20\.18\.2 and 21\.0\.0\-beta1 before 21\.0\.0\-beta3には、管理者およびストアフロントのOAuthにクロスサイトリクエストの偽造性が含まれている。単純なアクションは、フォームキーの検証なしでGETリクエストを受け入れる。アクションは、承認される。                                                                                                                                                                                                                          OAuth のコンシューマ資格を持つ攻撃者は、ログインした管理者または顧客に、攻撃者の要求トークンを承認する承認済み URL を引き渡し、それを /oauth/token で引き換えて、被害者に永続的な REST API アクセストークンを割り当てます。。は、\.クライアントは、クライアントがクライアントに通知したアクセストークンにアクセスできる。\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\. 認証\.\.\.   \.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.\.    \.\.\.\.\.\.  \.\.\.

## 原文

OpenMage Magento LTS before 20\.18\.2 and 21\.0\.0\-beta1 before 21\.0\.0\-beta3 contains a cross\-site request forgery vulnerability in the admin and storefront OAuth confirm and confirmSimple actions, which accept GET requests without form\-key validation\. Attackers holding OAuth consumer credentials can lure a logged\-in administrator or customer to a crafted confirm URL that authorizes the attacker's request token, then exchange it at /oauth/token for a persistent REST API access token bound to the victim\.
