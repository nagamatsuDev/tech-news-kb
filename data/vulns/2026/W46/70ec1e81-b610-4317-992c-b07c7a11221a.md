# Nuxt\: Incomplete fix for GHSA\-9v7c\-q64q\-vv33\: a leading \`//\` in the request path bypasses \`server/middleware\` path checks and server route rules on page routes

- **ID**: CVE\-2026\-128077 / GHSA\-r99w\-jh2x\-3mg9
- **危険度**: Medium（警告） (CVSS 6.5)
- **言語**: JavaScript/TypeScript
- **パッケージ**: npm/@nuxt/nitro\-server &gt;\= 4\.6\.0, &lt; 4\.6\.4 → 4\.6\.4
- **公開**: 2026-11-13

## 原文

\#\#\# Summary Since \`4\.6\.0\`, Nuxt parses a request path that starts with \`//\` as a URL with a host before rendering a page, so \`//x/admin\` renders the page at \`/admin\`\. Nitro's routing, Nitro's route rules and \`server/middleware\` see the path as \`//x/admin\`, so server\-side checks keyed on \`/admin\` do not apply\. The fix for \[GHSA\-9v7c\-q64q\-vv33\]\(https\://github\.com/nuxt/nuxt/security/advisories/GHSA\-9v7c\-q64q\-vv33\) in \`4\.6\.3\` covered dot segments but not this form\. \#\#\# Impact An unauthenticated attacker can bypass server\-side controls that match on the request path of a page route\.
