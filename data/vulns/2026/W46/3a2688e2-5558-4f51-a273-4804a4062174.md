# Building a malicious package that uses cgo could bypass "\#cgo LDFLAGS" validation and cause unexpected code execution at build time, or c\.\.\.

- **ID**: CVE\-2026\-97043
- **危険度**: High（重要） (CVSS 8.8)
- **公開**: 2026-11-11

## 原文

Building a malicious package that uses cgo could bypass "\#cgo LDFLAGS" validation and cause unexpected code execution at build time, or cause the go command to panic, via crafted quoting in "//go\:cgo\_ldflag" directives\. When "cmd/cgo" generates "\_cgo\_gotypes\.go", it quotes each "\#cgo LDFLAGS" argument with strconv\.Quote in a "//go\:cgo\_ldflag" directive, but "cmd/compile" and "cmd/go" parsed those directives by splitting on raw quote characters without handling backslash escapes or unquoting the string\. This mismatch allowed disallowed linker flags or unvalidated linker search paths to be smuggled past the go command's flag checks and passed to the external linker\. In addition, deduplicating LDFLAGS in the go command could panic with an out\-of\-bounds slice index when a prefix of the flag list matched near the end of the slice\. "cmd/compile" and "cmd/go" now properly handle backslash\-escaped quotes and unquote "//go\:cgo\_\*" pragma strings with strconv\.Unquote, and the slice bounds check in processCgoOutputs has been fixed\.
