# The WPML Multilingual CMS plugin for WordPress is vulnerable to Authentication Bypass via Race Condition in versions up to, and including\.\.\.

- **ID**: CVE\-2026\-76877
- **危険度**: High（重要） (CVSS 8.1)
- **言語**: PHP
- **公開**: 2026-11-10

## 原文

The WPML Multilingual CMS plugin for WordPress is vulnerable to Authentication Bypass via Race Condition in versions up to, and including, 4\.9\.7\. This is due to the \`process\_iframe\_request\` function's language\-per\-domain SSO handler generating the cross\-domain sign\-in token via \`wp\_create\_nonce\('wpml\_sso'\)\` on the logout landing page, where the browser has already discarded its authentication cookies — so \`wp\_get\_session\_token\(\)\` returns an empty string and the token collapses to the shared anonymous nonce for the current 12\-hour tick rather than a user\-bound secret — and then storing it in the \`wpml\_sso\_user\_&lt;token&gt;\_&lt;sha256\('wpml\_sso'\.\$domain\)&gt;\` transient mapped to the victim's \`user\_id\` with no binding to the specific sign\-out action or requesting client\. Because an unauthenticated attacker can independently derive the identical token by triggering the logout confirmation flow on \`wp\-login\.php?action\=logout\`, and because the \`is\_iframe\_request\(\)\` gate conditions \(the per\-domain SSO \`started\` transient and domain\-hash derived from the public constant \`SSO\_NONCE\`\) are fully computable within the 60\-second \`SSO\_TIMEOUT\` window, an unauthenticated attacker can submit the forged \`wpml\_sso\_token\_domain\` parameter with a \`wpml\_user\_signed\_in\` status to a secondary language\-domain endpoint before the legitimate \`wpml\_user\_signed\_out\` iframe fires, causing WordPress authentication cookies to be issued for the victim\. This makes it possible for unauthenticated attackers to gain access to accounts of users — including administrators — who are actively in the process of logging out during the race window\.
