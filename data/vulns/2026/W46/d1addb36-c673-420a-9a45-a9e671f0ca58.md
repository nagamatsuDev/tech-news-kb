# NLTK\: BllipParser passes caller\-supplied model paths to the bllipparser C extension with no pathsec check, enabling arbitrary read

- **ID**: CVE\-2026\-126295 / GHSA\-fg9w\-wfp5\-j933
- **危険度**: Medium（警告） (CVSS 6.8)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.10\.0, &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-13

## 原文

\#\# Summary \`BllipParser\` in \`nltk/parse/bllip\.py\` hands caller\-supplied filesystem paths to the native \`bllipparser\` C extension without routing them through NLTK's \`pathsec\` validation\. The constructor parameters \`parser\_model\`, \`reranker\_features\`, and \`reranker\_weights\`, and the alternative \`from\_unified\_model\_dir\(\)\` entry point, flow directly to the C extension's \`load\_parser\_model\(\)\` and \`load\_reranker\_model\(\)\` calls, which open and read the given path at the OS level\. Any application that passes an attacker\-influenced path to this API reads a file of the attacker's choosing from anywhere
