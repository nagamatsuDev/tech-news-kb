# Improper Handling of Highly Compressed Data \(Data Amplification\) vulnerability in elixir\-grpc grpc\_core and grpc allows unauthenticated a\.\.\.

- **ID**: CVE\-2026\-121808
- **危険度**: High（重要） (CVSS 8.2)
- **公開**: 2026-11-13

## 原文

Improper Handling of Highly Compressed Data \(Data Amplification\) vulnerability in elixir\-grpc grpc\_core and grpc allows unauthenticated attackers to exhaust server memory via a compressed Erlang external term in a gRPC message body\.
  
GRPC\.Codec\.Erlpack\.decode/2 \(grpc\_core/lib/grpc/codec/erlpack\.ex, and lib/grpc/codec/erlpack\.ex before the package split\) passes the message body to \:erlang\.binary\_to\_term/2\. That function inflates a compressed term in full before it returns\. The codec sets no limit on the decoded size, and its type checks run only on the decoded term\. The server's max\_body\_size limit counts the compressed bytes of the request\. A request with Content\-Type\: application/grpc\+erlpack can therefore make the server allocate a term much larger than the request body\.
  
This issue affects grpc\: from 0\.4\.0 before 1\.0\.0; grpc\_core\: from 1\.0\.0 before 1\.1\.0\.
