# NLTK\: Quadratic CPU exhaustion in TreebankWordTokenizer\.span\_tokenize via list\.pop\(0\) in quote\-restore loop

- **ID**: CVE\-2026\-126300 / GHSA\-ffr9\-mgrr\-wcvr
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.2\.5, &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-13

## 原文

\#\# Summary \`TreebankWordTokenizer\.span\_tokenize\` in the NLTK tokenizer package contains an unguarded O\(n\^2\) processing loop in its quote\-restoration step\. When the method is invoked on text containing a long run of double\-quote characters \(for example \`'"' \* n\`\), it performs a \`list\.pop\(0\)\` operation once per quote token, and because \`list\.pop\(0\)\` is O\(length\), the total cost grows with the square of the input length\. An attacker who can supply untrusted text to this public span\-tokenization API can force a single request to saturate one CPU core for a prolonged period, degrading availability\.
