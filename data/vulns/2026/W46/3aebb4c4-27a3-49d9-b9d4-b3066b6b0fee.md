# The simulated EEPROM driver validated access ranges in eeprom\_range\_is\_valid\(\) \(drivers/eeprom/eeprom\_simulator\.c\) with a single test, \(o\.\.\.

- **ID**: CVE\-2026\-90833
- **危険度**: High（重要） (CVSS 7.8)
- **公開**: 2026-11-10

## 原文

The simulated EEPROM driver validated access ranges in eeprom\_range\_is\_valid\(\) \(drivers/eeprom/eeprom\_simulator\.c\) with a single test, \(offset \+ len\) &lt;\= config\-&gt;size\. Because offset is a signed off\_t and len an unsigned size\_t of the same rank, the addition is evaluated in unsigned arithmetic\: a negative offset combined with a compensating len wraps the sum back into the accepted range\. eeprom\_sim\_read\(\) and eeprom\_sim\_write\(\) then memcpy\(\) through the EEPROM\(addr\) macro, which is plain pointer arithmetic on the driver's static mock\_eeprom array, so the copy addresses memory located before that array\.
  
eeprom\_read\(\) and eeprom\_write\(\) are \_\_syscall entry points, and their verification handlers in drivers/eeprom/eeprom\_handlers\.c check only the device object and the caller's own data buffer \(K\_SYSCALL\_MEMORY\_READ/K\_SYSCALL\_MEMORY\_WRITE\) — the offset argument is passed to the driver unvalidated\. With CONFIG\_USERSPACE\=y, a CONFIG\_EEPROM\_SIMULATOR device instance, and the device object granted to a user thread \(the usage the in\-tree tests/drivers/eeprom/api suite exercises from ZTEST\_USER threads\), an unprivileged thread could supply a negative offset and have the kernel perform the copy on its behalf\.
  
The result is an out\-of\-bounds read of kernel \.bss returned into the caller's buffer and, via the write path, an out\-of\-bounds write of caller\-supplied bytes over kernel memory preceding mock\_eeprom\. Both the start address and the length of the affected span are attacker\-selected, so the primitive is sufficient to corrupt adjacent kernel state and escape the user\-mode sandbox\. Exposure is limited to builds that instantiate the simulated EEPROM \(status \= "okay" by default on qemu\_x86 and native\_sim, otherwise added by a devicetree overlay\) together with userspace isolation\.
  
The fix rejects negative offsets and performs the remaining bound check without overflow\.
