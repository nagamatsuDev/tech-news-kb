## 原文

Building a package containing a crafted "\.syso" file could bypass cgo flag validation and inject arbitrary linker flags when linking\. When loading "\.syso" entries from a package archive, the linker only checked for recognized host object headers \(ELF, Mach\-O, PE, and XCOFF\) before falling through to Go object parsing\. A "\.syso" file beginning with a "go object" header was parsed as a Go compiler object, allowing untrusted cgo metadata directives \(such as "cgo\_ldflag" or "cgo\_dynamic\_linker"\) embedded in the "\.syso" file to be passed to the external linker without validation\. Additionally, "\.syso" filenames longer than 16 bytes lost their "\.syso" extension when truncated in archive headers, and unrecognized "\.syso" formats forced external linking in pure\-Go builds\. The linker now rejects "\.syso" files that are not recognized host object formats, and "cmd/go" and "cmd/pack" preserve the "\.syso" suffix when truncating long archive member names\.
