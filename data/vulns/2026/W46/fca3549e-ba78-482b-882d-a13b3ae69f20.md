# NLTK\: Quadratic CPU exhaustion in LegalitySyllableTokenizer\.tokenize via unguarded onset reversal loop

- **ID**: CVE\-2026\-126301 / GHSA\-gpwc\-27cw\-rh9r
- **危険度**: Medium（警告） (CVSS 5.3)
- **言語**: Python
- **パッケージ**: PyPI/nltk &gt;\= 3\.6, &lt;\= 3\.10\.3 → 3\.10\.4
- **公開**: 2026-11-13

## 原文

\#\# Summary \`LegalitySyllableTokenizer\.tokenize\` in the NLTK tokenizer package contains an unguarded O\(n\^2\) processing loop\. When the method is called on a single token that consists of a long run of vowels \(for example \`"a" \* n\`\), it consumes CPU time proportional to the square of the token length\. An attacker who can supply an untrusted token to this public tokenizer API can force a single request to saturate one CPU core for a prolonged period, degrading availability of any service that syllabifies attacker\-controlled text\.
