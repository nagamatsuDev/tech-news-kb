# A re\-entrancy flaw in Node\.js HTTPS lets an unauthenticated client read memory belonging to other connections, including TLS private keys\.\.\.

- **ID**: CVE\-2026\-123864
- **危険度**: High（重要） (CVSS 8.1)
- **言語**: JavaScript/TypeScript
- **公開**: 2026-11-11

## 原文

A re\-entrancy flaw in Node\.js HTTPS lets an unauthenticated client read memory belonging to other connections, including TLS private keys and other users' requests\. TLSWrap\:\:DoWrite\(\) calls ClearOut\(\) directly when asked to write zero bytes; if that write is issued from JavaScript running inside the HTTP parser's on\_body callback, ClearOut\(\) decrypts the next TLS record while the parser is still mid\-body, re\-entering llhttp\_execute\(\) and causing a use\-after\-free and an out\-of\-bounds heap read\. The server then copies that freed or unrelated heap memory into the response for the request body\. Triggering it requires a handler that calls res\.flushHeaders\(\) before the request body ends and later calls res\.end\(\) with a non\-empty chunk, and reading the leaked memory requires any ordinary route that echoes or stores a request body\. Cleartext node\:http is not affected\. This vulnerability affects Node\.js 26\.x, 24\.x, and 22\.x\.
