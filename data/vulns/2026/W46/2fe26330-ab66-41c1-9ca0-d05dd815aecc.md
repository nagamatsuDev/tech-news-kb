# JSON\:\:XS versions from 4\.0\_00 before 4\.05 for Perl corrupt the incremental buffer length by chopping past its end in incr\_skip after a to\.\.\.

- **ID**: CVE\-2026\-129113
- **危険度**: Critical（緊急） (CVSS 9.1)
- **公開**: 2026-11-14

## 原文

JSON\:\:XS versions from 4\.0\_00 before 4\.05 for Perl corrupt the incremental buffer length by chopping past its end in incr\_skip after a top\-level number\.
  
The incremental parser scans any run of digits, signs, dots and exponent markers as one number, but the decoder stops at the end of a valid number, so the parser keeps an offset into bytes it has not decoded\. It then empties the buffer without clearing those bytes, and a later incr\_parse call without new input reads them again and moves the offset past the end of the buffer\. incr\_skip, the documented recovery after an error, removes that many bytes and the buffer length wraps\.
  
A peer sending input such as "1\-2" to an incr\_parse consumer can make the next read of incr\_text exit the process through perl's uncatchable out\-of\-memory path\.
