# The Widget Options – Advanced Conditional Visibility for Gutenberg Blocks &amp; Classic Widgets plugin for WordPress is vulnerable to Code In\.\.\.

- **ID**: CVE\-2026\-116615
- **危険度**: High（重要） (CVSS 8.8)
- **言語**: PHP
- **公開**: 2026-11-13

## 原文

The Widget Options – Advanced Conditional Visibility for Gutenberg Blocks &amp; Classic Widgets plugin for WordPress is vulnerable to Code Injection in all versions up to, and including, 4\.2\.6\.1 via the \`post\_content\` parameter\. This is due to asymmetric parsing between the save\-time strip filter \(\`widgetopts\_strip\_logic\_from\_blocks\(\)\`\) and the render\-time parser \(\`blockopts\_filter\_before\_display\(\)\`\)\: embedding an inner \`&lt;\!\-\-start\_widgetopts\` literal inside a JSON key causes the write\-side \`json\_decode\` to see a non\-\`class\` key and skip stripping — persisting the payload verbatim to the database — while the render\-side \`str\_replace\` reconstitutes the key to \`class\`, feeding the attacker\-controlled \`logic\` value directly into \`@eval\`\. This makes it possible for authenticated attackers, with Author\-level access and above, to inject PHP expressions that execute on every front\-end page view, enabling boolean\-oracle exfiltration of WordPress site configuration data — including admin email address, default role, and arbitrary \`get\_option\`, \`get\_user\_meta\`, and \`get\_post\_meta\` values — via the plugin's allowlisted\-function sandbox, which escalates to unrestricted code execution if any installed plugin extends the \`widgetopts\_allowed\_php\_functions\` filter\. Contributors can also exploit this vulnerability when their submitted post is later published by an administrator; notably, the injected payload executes for all site visitors, including unauthenticated users, because a trust\-flag mechanism introduced in version 4\.2\.6 causes \`widgetopts\_safe\_eval\_trusted\(\)\` to bypass its non\-admin short\-circuit at every legacy render callsite\. Exploitation by attackers with contributor\-level access and above requires that an administrator \(or editor\) later publishes the contributor's submission\. On a default installation, where that is not configured, the vulnerability requires attackers with author\-level access and above\.
